# 真实对局测试计划（Playtest Plan）

> 目的：把"改完就算完"变成"真的打几局看有没有问题"。
> 执行方式：**我扮演玩家**（脚本化操作 + 逐局记录），按下面 P0→P7 顺序跑；真 API 阶段受预算硬约束。
> 状态：**待你确认后执行**。确认前不动一行代码、不花一次额度、不打包。

---

## 0. 这份计划要回答什么（判定问题）

按优先级排序，每条都有明确的通过标准：

| # | 要回答的问题 | 通过标准 |
|---|---|---|
| Q1 | 改造后（四刀 + medium + tier 收紧）**丝滑度**到底有没有变好？ | 真局里语音类决策 p50 ≤ 45s、p90 ≤ 90s；不再出现 >200s 的单次发言 |
| Q2 | 有没有**假死/假降级**？看门狗会不会误判流式仍在输出？ | 42 分钟以上长局中，误报"推送中断"次数 = 0；真断线时 30s 内自动恢复推送 |
| Q3 | 预算用尽时（E1）**补救是否真的发生并救回局面**？ | 触发轻量补救的场合，2 次调用内收束；不再出现"我过。"式静默降级 |
| Q4 | AI 是否**真的零幻觉/零信息泄漏**？ | `isolationProblems = 0`；人工抽检发言不出现私有信息（验人结果、狼队友、女巫用药） |
| Q5 | 人类视角的**操作体验**有没有坑？ | P2-b/P3-a/P3-c 相关的 6 条用例全过（详见 P4） |
| Q6 | 服务商侧问题（配额、延迟毛刺）**是否被优雅处理**？ | 429 时暂停 + 明示 + 可恢复；恢复后不丢档 |
| Q7 | 一局真实成本多少？ | 产出 calls/局、prompt+completion tokens/局、折算的资源包消耗 |

## 1. 环境与红线

**隔离（最重要）**：绝不污染你的正式数据。

| 项 | 正式（你用的） | 测试（本次新建） |
|---|---|---|
| 端口 | 3210 | **3211** |
| 数据目录 | `D:\werewolf-ai`（含 61+ 存档） | **`%TEMP%\ww-playtest`**（跑完整个删掉） |
| 存档 | `saves/` **禁动** | 测试自己的 saves，随便造 |
| 日志 | `logs/` | 测试目录下的 logs（基准对比不混） |
| 配置 | `config.json`（真实 key） | **只读复用同一份**（测试实例也读 `config.json`，不改它） |

启动测试实例：

```powershell
$env:PORT='3211'; $env:NO_OPEN='1'; $env:WW_DATA_DIR="$env:TEMP\ww-playtest"
node server.js
```

**红线（执行期间始终有效）**

1. **不打包**：不生成 APK、不生成桌面 exe（沿用你的指令）。
2. **不动 `saves/`**、不改 `config.json`（密钥只以 `319c****MOi6` 形式出现，不打印明文）。
3. 出现 `429 余额不足或无可用资源包` → **立即停止真 API 阶段**，转 mock 阶段继续，并报告已消耗量。
4. 任何"跑不下去"的阻断性 bug：当场做**最小修复**并明确标注；其余问题只记录，等你点头再改。
5. 每个真 API 阶段结束后立刻汇总消耗（calls / tokens），供你决定是否继续。

## 2. 工具盘点

**现成可用（已核实存在于仓库）**

| 工具 | 命令 | 用途 | 成本 |
|---|---|---|---|
| 门禁 | `npm run gate` | lint + eslint + coverage + eval，Δ 必须 0 | 免费 |
| 引擎批量评测 | `npm run eval` | mock 30 局，确定性，含 `isolationProblems` | 免费 |
| 批量模拟 | `npm run simulate --n=50` | mock 大批量对局（规则/流程回归） | 免费 |
| **真局批量** | `node scripts/eval/eval-harness.js --live --games=N --max-calls=M` | 真实 LLM 跑整局，产出投票/查验命中率、悍跳存活率、token 成本、p90 延迟；**`--max-calls` 是硬熔断** | 真 API |
| 丝滑度回放 | `npm run bench:pace` | 用**真实调用日志**回放算延迟分位 | 免费 |
| UI 几何/命中测试 | `npm run ui:check` | CDP 真实鼠标事件（含 `realClick` / `realHover`）+ 截图 | 免费 |
| Key 并发探测 | `npm run probe:concurrency` | 探测每个 key 的实际并发额度 | 极少 |

**需要新建（本计划的两个主要开发项，先做 P1 再做 P4）**
1. `scripts/fake-llm.js` —— **本地假 LLM（OpenAI 兼容）**，按开关注入故障：
   `--mode=ok|quota429|slow-first-token|slow-total|truncated-json|bad-json|empty|http500|drop-mid-stream`
   价值：把"服务商侧故障"变成**确定性、零成本**的测试对象（E1/E3/P1/配额暂停全靠它验证）。
2. `scripts/playtest.js` —— **浏览器玩家harness**：CDP 驱动真实网页版，创建对局 → 轮询 `/view` 等人类操作 → 截图 → 按剧本提交 `/action` → 记录时间线（含横幅文本、按钮可用性、页面 JS 异常）。
   复用 `scripts/ui-check.js` 里已有的 `Browser` 类（`goto/eval/click/realClick/realHover/setOffline/shot`）。

3. **P1 的前置改动（必须先做，否则有污染正式配置的风险）**：加一个环境变量 `WW_CONFIG=<路径>`，
   指定配置文件位置（缺省仍是仓库根的 `config.json`，**默认行为完全不变**，约 2 行）。
   原因：服务端写死了 `ROOT/config.json`，而且**设置页保存也写这一份** —— 如果测试实例直接改端点指向假 LLM，
   就会顺带把你的正式配置改掉。加了它以后，测试实例指向 `%TEMP%\ww-playtest\config.fake.json`，
   正式配置**从进程层面既读不到也写不到**（这是 P1 能安全做的前提，不是可选项）。

## 3. 执行阶段

### P0 环境自检（免费，约 10 分钟）

| 步骤 | 命令 | 通过标准 |
|---|---|---|
| P0-1 | `npm run gate` | Δ 全 0（改造后基线） |
| P0-2 | `npm run eval` | 30 局全过、`isolationProblems = 0` |
| P0-3 | `npm run ui:check` | 全过（含新增的 6 条断言） |
| P0-4 | 起 3211 测试实例 | `/api/config` 返回 medium/8000；`/m/` 有 `#m-mock-btn` |
| P0-5 | **实测单局调用量** | 用 mock 局 + 真局各 1 局统计 `llmStats.calls`，**据此校正 P3/P4 的 `--max-calls`**（计划里 800 是暂定值） |

> P0-5 是后面所有预算数字的来源。不先测出"一局多少次调用"，真 API 阶段的熔断就是拍脑袋。

### P1 故障注入（本地假 LLM，**零成本、确定性**，约 40 分钟）

把测试实例指向 `fake-llm.js`（测试实例用 `WW_CONFIG` 指向 `%TEMP%\ww-playtest\config.fake.json`，
**正式 `config.json` 全程不被读写**）。每例都是"跑一局 → 观察日志与界面"。

| 用例 | 注入 | 预期（不通过就是 bug） |
|---|---|---|
| P1-1 配额暂停 | `--mode=quota429` | 服务端暂停对局 + 返回 `paused`；前端出现"配额/套餐"横幅；**不崩、不丢档**；恢复后能从断点续跑 |
| P1-2 慢首字 | `--mode=slow-first-token`（首字 > 36s） | 看门狗（36s）与心跳（16s）配合：**不得误判**；真超时就明示"推送中断"且可自动恢复 |
| P1-3 慢整体 | `--mode=slow-total`（快速任务 > 30s） | 触发降档重试（E3 机制），日志可读；不静默失败 |
| P1-4 截断 JSON | `--mode=truncated-json` | 校验失败 → 带提示重试 →（超预算时）**轻量补救恰一次** → 仍失败才降级；调用次数 ≤ 2 上限 |
| P1-5 非法/空回复 | `--mode=bad-json` / `empty` | 同上，且降级事件标注 `cheap` 字段 |
| P1-6 流中断 | `--mode=drop-mid-stream` | 前端出现**单例**状态条"…已转为轮询（每 30s 自动尝试恢复）"；30s 内重连成功并撤掉提示（P2-a 的真实验证） |
| P1-7 网络离线 | 浏览器侧 `setOffline(true)` → 15s → `setOffline(false)` | 同 P1-6；横幅只出现一条（不得堆积多条） |
| P1-8 缓存字段为 0 | `--mode=ok` 但 usage 里 `cached_tokens=0` | 告警措辞如实（"冷启动"），不误导成缺陷（E2） |
| P1-9 服务端 5xx | `--mode=http500` | 重试/降级路径可读，不死循环 |

### P2 引擎与规则批量（mock，免费，约 15 分钟）

| 用例 | 命令 | 预期 |
|---|---|---|
| P2-1 30 局回归 | `npm run eval` | Δ0、`isolationProblems=0` |
| P2-2 大批量 | `npm run simulate --n=50` | 无异常、无卡死 |
| P2-3 每块板子 | 各板子（含 `quick10`）各 5 局 | quick10 实测 **10 人**（P3-b 修复的端到端确认） |
| P2-4 无警长变体 | `npm run simulate -- --rules={"sheriff":false}` | 流程正常（警长相关分支不被误走） |

### P3 API 层真局（**真 API**，最贵，串行）

| 项 | 内容 |
|---|---|
| 命令 | `node scripts/eval/eval-harness.js --live --games=2 --max-calls=<P0-5 校正值>` |
| 目的 | AI 真实水平：投票命中率、查验命中率、悍跳存活率、**token 成本/局**、**p90 延迟**（回答 Q1/Q4/Q7） |
| 预期 | `isolationProblems = 0`；p50/p90 达到 Q1 标准；产出成本表 |
| 实测耗时 | **单 API Key = 1 并发 → 天然串行**，一局约 1.5–2 小时（真实数据：平均单局 42 分钟，AI 全自动会更久） |
| 熔断 | 达到 `--max-calls` 立即停；遇 429 立即停 |

> 若 P0-5 显示单局调用量很大，优先改用 `quick10`（10 人局）跑 P3，成本与时长都按比例下降。

### P4 人类视角真局（**真 API + 浏览器**，我扮演玩家，2–3 局）

用 `scripts/playtest.js` 打，每局一个剧本（见第 4 节）。**每局都记录**：决策等待时长、横幅文本、按钮可用性、JS 异常、截图序列。

| 用例 | 步骤 | 预期 |
|---|---|---|
| P4-1 恢复卡片详情 | 开局后刷新页面 | 卡片显示**人数 / 第几天 / 试玩还是真局 / 存档多久前**（P3-a） |
| P4-2 试玩播报 | 手机端点试玩开关后开局 | 开关文案切换 + 开局播报"不调用 API、不消耗额度"（P2-b） |
| P4-3 空刀拦截 | 狼局夜晚**不选目标**直接点"投刀" | 明确提示"请先点一个座位选出刀口"，**不发出去**；选了之后能正常投（P3-c） |
| P4-4 终止→刷新 | 点"结束本局"后刷新页面 | 不再被当活局恢复进死局界面；卡片不再提示可继续（P2-c） |
| P4-5 断点恢复 | 对局中杀掉服务端 → 重启 → 打开页面 | 出现"发现中断的对局（服务重启过）（…详情）"，恢复后能从锚点续跑 |
| P4-6 人类不操作 | 我的回合故意放置 5 分钟 | AI 与流程**干等不崩**，无超时踢人、无重复提交 |
| P4-7 边界操作 | 空发言跳过 / 退水 / 放弃开枪 / 连点两次确认 | 均有明确反馈；不产生幽灵操作；不重复计票 |
| P4-8 观战视角 | 切到上帝视角 | 角色信息与事件流一致，无泄漏到玩家视图（对照 `isolationProblems`） |

## 4. 我扮演玩家的剧本

每局固定一个身份，**故意做出真实玩家会做的操作**（包括"不好的操作"），因为很多坑只在坏操作下出现。

| 局 | 我的身份 | 我要做什么 | 重点观察 |
|---|---|---|---|
| 1 | 平民 | 正常发言、跟票、偶尔空过 | 基线体验、丝滑度、事件流可读性 |
| 2 | 预言家 | 上警、跳预言家、报验人、被悍跳对抗 | 警长流程、claim 一致性、信息隔离 |
| 3 | 狼人 | 悍跳预言家、夜晚投刀（**先故意不选目标**）、被放逐后的遗言 | 狼队协作、**P3-c 空刀拦截**、遗言路径 |
| 4 | 女巫 / 猎人 | 用药时机、放弃开枪、被刀后的反应 | `allowNone` 分支、技能时序 |
| 5 | 平民（手机端） | 手机端打一局，中途刷新页面 | 移动端 UI、恢复卡片、P5 |

**每局都要走的边界操作清单**：不发言直接跳过 → 退水 → 放弃开枪 → 人类回合放置不操作 → 刷新页面 → （P1 阶段已验）断网重连 → 结束本局后刷新。

## 5. 度量与证据

**从日志解析**（测试实例的 `logs/game-*.log`，字段已核实存在）：

- 每次调用：`task / seat / promptTokens / cachedTokens / completionTokens / latencyMs / ttftMs`
- 重试与补救：attempt 序号、`_retryNote`、`cheap` 标记、`llm_error`
- 降级与暂停：`paused`、`配额`、降级事件
- 界面侧（playtest.js 采集）：横幅文本与出现次数、按钮 disabled 状态、页面 JS 异常、截图序列

**产出指标表**（每阶段一张）：

| 指标 | 计算 | 对照 |
|---|---|---|
| 语音类延迟 | p50 / p90 / max | 旧基线：avg 103.6s、p90 12000ct、max 362.3s |
| 解码速率 | completion tokens / 解码耗时 | 旧基线 30.2 tok/s |
| TTFT 占比 | ttft / latency | 旧基线 15% |
| 缓存命中 | cached / prompt | 冷启动 0%、立刻重发 93%（已实测） |
| 轻量补救触发 | 次数 + 是否成功 | 预期：每次都能在 2 次调用内收束 |
| 假降级次数 | 状态条出现次数 − 真断线次数 | 预期 0 |
| 信息隔离 | `isolationProblems` | 预期 0 |
| 成本 | calls/局、tokens/局 | 用于 P7 决策 |

**问题记录格式**（每条都要有证据，不接受"感觉不对"）：

```
[严重级 P0/P1/P2/P3] 一句话标题
复现：精确步骤（第几步、点了什么）
证据：日志行原文 / 截图文件名 / 指标数字
期望：…    实际：…
影响：…    建议修法：…
```
