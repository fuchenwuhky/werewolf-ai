## 5. FIN-01：HTML 条件缓存与资源哈希闭环

### 5.1 已确认的问题

当前 [静态服务](../src/static.js)先用源 HTML 的文件 stat 生成 ETag 并处理 `If-None-Match`，再执行 `sendHtml()` 资源引用改写。旧 HTML 与改写后的新 HTML 因源文件不变得到相同 ETag，浏览器收到 304 后继续使用无版本脚本 URL。`_htmlCache` 同时仅以 HTML mtime 判断复用，遗漏 JS/CSS 依赖变化。

修复目标：缓存校验针对**实际发送的表示内容**；首次升级不能依赖手动清缓存、连续刷新或先让新 Worker 激活。

### 5.2 推荐实现顺序

1. 将 HTML 与普通静态资源的响应路径分开。普通图片、JS/CSS 的既有响应头不为此一并改写。
2. HTML 路径先读取源内容、解析本地资源引用、取得依赖版本，再生成最终响应体。
3. 从最终响应字节生成 HTML ETag；其命名空间与旧的 stat ETag 区分，不能把旧 ETag 误判为新表示未变化。
4. **生成新表示后**比较 `If-None-Match`：一致才 304，否则 200＋新 HTML。304 保留必要的 ETag、缓存校验响应头；200 保留现有 CSP 与内容类型。
5. 输出缓存的 key 至少覆盖 HTML 内容标识、解析规则版本、每个本地 JS/CSS 的内容标识。只改 `app.js`、`m.js` 或共享模型，也必须产生新的引用 URL 和新的 HTML ETag。
6. 可以用依赖 stat 辅助减少读盘，但不能将“只有 HTML mtime 没变”作为最终依据。构建清单／内容哈希可以在构建期缓存；运行时允许热更新则需依赖失效机制，并测同进程更新。
7. 同一 URL 的表示应稳定。发布时原子切换资源集合；新 HTML 不得引用尚未落盘的文件，不得在旧哈希 URL 下错误缓存另一份内容。
8. 保持双端相对路径、父级路径、根路径语义；外链保持原样；不存在的资源继续明确 404，不伪装为首页。
9. Service Worker 继续排除所有 `/api/*`；不以强制 `skipWaiting` 中断对局作为修复方案。已有离线能力、首次安装不自动闪屏等规则保留。
10. 若采用临时止血，允许先对 HTML 明确禁用条件 304 并取消错误的输出缓存；但最终仍需完成依赖正确性，不能只换一个版本字符串交付。

### 5.3 必测用例

| 编号 | 起始状态与操作 | 通过标准 |
| --- | --- | --- |
| C01 | 保存旧无版本 HTML 和其 ETag，再启动新服务携带旧 ETag 请求 | 200；最终 HTML 为版本化引用；ETag 与旧表示不同 |
| C02 | 新 HTML 取得 ETag 后不改任何文件，再条件请求 | 正确 304；不能通过永久随机 ETag 掩盖问题 |

## 6. FIN-02：回滚状态不能取决于恢复记录是否写成功

### 6.1 已确认的问题

[导入实现](../src/api.js)在发现残留后尝试写恢复记录；写失败把 `recoveryFile` 置空，随后落到 `rolledBack:true` 的返回分支。实测可残留一个新档案、没有恢复记录，却提示“已回滚本次写入”。

### 6.2 必须实施的状态模型

| 实际状态 | rolledBack | cleanupPending | 恢复记录状态 | 对用户说明 |
| --- | --- | --- | --- | --- |
| 导入全部成功 | 不返回回滚成功标识 | false 或省略 | 无 | 导入完成及实际局数／笔记数 |
| 导入失败，清理核实无残留 | true | false | 不需要 | 导入失败，本次新增内容已清理 |
| 导入失败，仍有残留，恢复记录保存成功 | false | true | 已保存 | 故障解除后可重试清理，显示可查的恢复编号 |
| 导入失败，仍有残留，恢复记录也写失败 | false | true | 未保存 | 明示自动恢复依据未落盘；保留残留清单，不能承诺重启后自动找回 |

实施要点：

1. 用 `residue` 与档案清理核验结果直接计算 `cleanupComplete`，与 `recoveryFile` 是否存在解耦。
2. 统一异常出口：校验错误使用既有 4xx；实际文件系统故障为数值 500。`EPERM`、`ENOSPC` 等字符串不能作为 HTTP 状态。
3. 建议补充 `recoveryPersisted`、`profileId`、残留相对文件清单、恢复编号等管理端字段；这是新增建议契约，实施时在 API 文档中定名并加测试。不要把完整本机路径或凭证放入公开日志／公共 SSE。
4. 临时文件、已落地文件、档案索引和档案目录分别核验。回收区中的正常归档证据与未完成残留分开，不把成功移入回收区视作数据丢失。
5. 恢复记录采用完整写入及原子落地策略；损坏记录需保留并报告，不能因为解析失败便假装已处理。
6. 恢复操作幂等：已不存在的目标可视为已清理，但读权限错误／损坏索引不能一概当“不存在”。
7. 清理目标必须在预期的数据根内，校验档案 ID、文件形态与解析后的绝对路径；恢复记录中不能携带可删除任意位置的无约束路径。
8. 下一次导入自动重试的现有机制保留；设置“设备与数据”提供查看待清理状态与手动重试入口。重试不能重复创建导入档案，也不能无提示覆盖正在编辑的档案。
9. 恢复记录写不下时，至少保留当前响应中的恢复信息和可见错误；允许用户主动复制／保存诊断。磁盘持续故障时不能以无限后台重试代替告知。
10. 仅修复事务边界与错误语义，不借机迁移数据库。若需要拆分导入服务，可从 `src/api.js` 提取小模块，但真实路由、内部调用与测试必须共用一个实现。

### 6.3 必测用例

| 编号 | 故障组合 | 通过标准 |
| --- | --- | --- |
| R01 | 笔记写失败，清理成功 | 500、rolledBack:true；无活动新档案／存档／tmp 残留 |
| R02 | 笔记写失败＋文件删除或档案回收失败 | rolledBack:false、cleanupPending:true；记录与真实残留对应 |
| R03 | R02 再叠加恢复记录写失败 | 仍为 rolledBack:false；明确记录未保存；响应含足够的人工恢复信息 |
| R04 | 存档 rename 失败，tmp 已生成 | tmp 清理成功才可称完全回滚；失败走待清理状态 |
| R05 | 恢复记录存在，解除故障，下一次导入／手动重试 | 清理后核实无残留，再删除记录；重复重试无副作用 |
| R06 | 恢复记录损坏、目标已不存在、访问被拒绝 | 三类分别处理；损坏／拒绝不误报已完成 |
| R07 | 半坏包、notes 类型错误、未来主版本、超限包 | 在新数据落盘前拒绝；不改变现有档案 |
| R08 | 正常包真实 HTTP 导入→导出 | 笔记、偏好、事件、映射引用正确；无凭证泄漏；正常路径不因整改退化 |

残留断言按导入前后目录清单、事务生成的新 UUID 和记录清单检查；不能只搜索包内旧 gameId，因为导入已经重映射。

## 7. 统一视觉与交互施工基准

### 7.1 视觉方向：月夜狼冠

目标用户是需要长时间阅读发言、辨识座位和记录推理的狼人杀玩家。视觉的核心任务是“当前发生什么、我该做什么、哪些只是我的猜测”。

- 标志性元素：**银灰狼首＋古金纹章**。首页为主要展示位置，局中缩为低干扰标识；沿用已交付 SVG，不重新生成一套狼头。
- 色彩：午夜底 `#080D17`、板岩面 `#101A29`、抬升面 `#182438`、骨白正文 `#E7E6E0`、次级文字 `#A0AEC0`、古金强调 `#D8B777`；危险／怀疑与正向状态使用原方案语义色，并同时显示文字／图形。
- 字体：标题采用本地宋体类衬线，正文采用系统中文无衬线；分发额外字体前核实许可并自托管。不得依赖外部 Google Fonts 才能完成布局。
- 正文：电脑 14–16px、手机默认 16px；次级文字默认不低于 12px；发言行高 1.6–1.75。重要座位信息不靠缩成小字挤进屏幕。
- 装饰取舍：狼冠承担哥特识别；发言、投票、笔记采用安静的面板和清晰分隔。避免给每张卡都加花纹、强发光或常驻呼吸动效。
- 本计划采用 frontend-design 的设计原则，将品牌气质集中在狼首、标题和阶段分隔，具体阅读与操作控件服从可用性。参考稿需先与实际 12/13 人内容对照，再实施。

### 7.2 需要用户实际看见的变化

1. 首页第一屏是新狼头、当前档案、继续上局／开始新局，不是整页 API 参数。
2. 电脑局中出现稳定的座位区、发言区、笔记区；小窗口自然变抽屉。
3. 手机发言获得完整宽度，玩家和笔记有明确页签；固定操作区显示目标和动作。
4. 用户的推测与公开身份有不同结构和文字，不是只换颜色。
5. 正式安装后的应用图标、首页标识与关于页一致；设计预览页不算产品截图。

### 7.3 FIN-03：全局控件与触区

所有 Web 尺寸使用 CSS px。以下是本项目产品要求，不把它们冒充平台统一强制标准。

| 控件 | 电脑 | 手机／粗指针 |
| --- | --- | --- |
| 开始／投票／发言／技能确认 | 高≥44，主按钮宽≥112 | 高≥52，优先占主宽度 |
| 普通按钮、输入、下拉 | 高≥40 | 高≥48，输入字体默认≥16 |
| 返回、关闭、设置、笔记图标 | 40×40 | 48×48 |
| 紧凑工具操作 | ≥32×32 | ≥48×48 |
| 候选／倾向 chip | 高36–40 | 高44–48，实际命中区不重叠 |
| 玩家目标区域 | ≥64×72 | ≥96×96，独立笔记入口不嵌套 button |
| 加减／分页／列表行 | 40px 控件；行高≥48 | 48px 控件；行高≥56 |

统一 token 与组件 class，清理冲突的局部 `!important`；桌面触屏按粗指针适配。档案管理里的 48px 修复保留，但必须扫描设置、弹层、待确认面板、技能面板等全部入口。

状态必须有默认、hover、focus-visible、选中、禁用、处理中、成功、失败；禁用显示原因，处理中保持宽度，双击只产生一次业务提交，失败不清输入。中文 composing 期间 Enter 不发送。

模态统一管理：只允许一个最上层模态，背景不接收点击和 Tab，关闭后焦点回到来源。危险操作与主操作分离，说明具体对象。已经服务端接受的投票／发言不提供虚假的“撤销”。

## 8. FIN-04：首页、开局、设置和结算

### 8.1 首页与导航

| 页面区块 | 必须包含 | 行为 |
| --- | --- | --- |
| 品牌／当前档案 | 新狼头、应用名、头像与昵称、管理入口 | 明示“本机玩家档案”，不显示登录／退出登录 |
| 继续上局 | 当前档案的最近可恢复局、模式、阶段、暂停原因、保存时间 | 恢复前核对归属与模式；无可恢复局则隐藏卡或给出明确空态 |
| 开始新局 | 主要按钮、Mock 无费用说明、板子入口 | 无 Key 也可直接进入 Mock 路径 |
| 我的对局 | 进行中／暂停／结束／归档、真实／Mock 标识 | 请求与列表按档案过滤，切换后不短暂显示上一档案数据 |
| 资料与设置 | 规则、角色图鉴、AI 名册、设置、关于 | 低频配置不占据第一屏主体 |

手机首页底部至多四个主入口：开始、对局、资料、我的。局中切换为局内导航，不能叠加两套底栏挤占行动区。

### 8.2 开局流程

三步：板子与人数／规则 → 座位与 AI 来客 → 模式及配置确认。后退保留已填项，不重复创建对局。

确认页同时显示档案、板子、人数、我的座位策略、真实／Mock、模型配置状态。真实模式缺 Key 或绑定失效时阻止开始并引导设置；不能以“继续”按钮绕过门禁。点击开始到成功之间冻结本次 `profileId`，不读取随后切换的全局档案。

既有 AI 头像、名字、性格内容保留；长名字可在详情完整查看，不能把玩家退化为只有数字的占位圈。若并非所有 AI 都由用户手动配置，文案明确“随机分配”与“已选择”，不展示无效编辑入口。

### 8.3 设置分组

| 分组 | 归属 | 内容 |
| --- | --- | --- |
| 外观与操作 | 档案级，窗口／安全区为设备级 | 字号、阅读／紧凑布局、减少动态、已支持的声音／发送偏好 |
| 游戏默认偏好 | 档案级 | 常用板子、规则与座位偏好；不能修改已开始局的固定规则 |
| 模型与密钥 | 安装级 | 地址、模型、多 Key、绑定与测试；明确“此设备共享” |
| 设备与数据 | 安装级入口、操作指向指定档案 | LAN 配对、导入导出、待清理恢复记录、诊断 |
| 关于 | 安装级 | 产品版本、构建标识、运行端、帮助与许可信息 |

只展示确实接入的偏好；保存后应立即影响对应布局并在刷新／重启后保留。对尚未支持的选项不做可点击假开关。API 参数留空的语义、显式清空 Key、重新绑定流程保持原有安全约定。

### 8.4 结算与复盘

首层显示自然结束／手动终止／故障暂停、本人角色及最终阵营、得分依据和关键行动；第二层展开全员信息、时间线、个人标注与 AI 复盘。Mock、观战、平局不伪装为正式胜败。

复盘已有结果优先读取；生成中状态可恢复，失败可明确重试，但页面切换／刷新不得自动重复发起付费生成。事件过滤始终基于后端允许的视角，不让前端隐藏字段替代权限裁剪。

## 9. FIN-05：电脑端局中布局

```text
顶部：狼冠／当前档案／第几天与阶段／连接及保存状态
┌────────────┬─────────────────────┬──────────────┐
│ 座位列表   │ 发言与阶段时间线    │ 我的笔记     │
│ 圆桌可切换 │ 历史滚动／新消息提示│ 当前座位编辑 │
│ 独立笔记键 │                     │ 筛选／依据   │
├────────────┴─────────────────────┴──────────────┤
│ 当前任务＋已选目标＋一个主要确认操作             │
└────────────────────────────────────────────────┘
```

- ≥1280px：默认左 240px、中间弹性、右 300px；以实际容器可用空间为准，不将最小宽度相加后强行溢出。右栏可收起。
- 1024–1279px：右栏改抽屉；发言区优先，不硬塞三栏。更窄窗口采用紧凑重排，不依赖 User-Agent。
- 座位列表与圆桌共用数据和选择状态；切布局不清空笔记草稿、不改变目标、不得重新请求创建对局。
- 笔记入口常显，和选目标分开；公开身份、本人私密信息、我的推测分别呈现。
- 发言按天／阶段定位；新增文字不抢历史阅读位置，提供“有 N 条新发言”和回到最新按钮。
- 笔记宽度调整若实施，须支持键盘和恢复默认；不是本轮强制使用拖动才能操作。
- Electron 记忆窗口位置时处理显示器移除、缩放变化和窗口移到屏外；100/125/150/200% 缩放均能到达主要操作。
- 原有规则书、角色图鉴、God 调试等能力不能在重构时无意删除；调试高权限入口保持权限及明显提示，不混进普通推理笔记。

## 10. FIN-06：手机端布局与系统交互

```text
顶部：返回／阶段／状态／更多
局内页签：发言 | 玩家 | 笔记
主体：当前页内容，全宽阅读，可正常滚动
底部行动区：当前任务 → 已选目标 → 确认按钮
系统安全区：保留，不被按钮或文字占用
```

1. 发言页不再长期夹在两侧窄座位列中；玩家页使用网格，320px 等窄屏优先两列，空间足够时三列，每卡≥96px，保留头像、座位号、昵称、存活状态与推测摘要。
2. 任务区只展示当前阶段可执行动作；选择目标与确认分开，离开玩家页仍能看到目标。非法目标禁用并说明，死者可查看笔记但不能成为非法技能目标。
3. 底部使用安全区和动态视口适配。软键盘展开时输入、保存／发送可达，收起后不丢草稿、不重置历史滚动位置。
4. 长表单使用底部面板；短确认居中。面板高度同时受可视区域与键盘限制，背景不滚动；非保存成功、显式放弃或用户确认，不销毁草稿。
5. 返回优先级：关闭最上层面板 → 当前功能页返回 → 离开对局确认。不能一次返回既关闭编辑又退出对局；原生返回和页面返回行为一致。
6. 手机长按只能作为快捷方式，必须有可见入口；触区不能只在 hover 存在。
7. 检查 12/13 人、20 字昵称、双行阶段文案、空列表、加载失败和断网状态。不要通过减小正文来消除溢出。
8. 保留用户缩放能力；200% 字号下关键内容可重排，300% 场景至少可滚动访问，不出现唯一按钮不可达。
9. 手机文件导入／导出通过可用的系统文件选择、下载或分享能力完成；真机检查取消选择、分享返回、覆盖升级后访问与超限提示。
10. 切后台、锁屏、切网络后回前台，从服务端重新确认状态；不能沿用过期目标直接提交。

## 11. FIN-07：已有档案与标注能力的系统核验

本节是对原方案尚缺证据的要求做收口，**不是宣称以下每一项都已发现缺陷**。开工先逐项标“已满足＋证据”或“需补实现”。

| 核验面 | 必须成立的契约 |
| --- | --- |
| 当前档案与 owner | 每客户端独立选择；对局 owner 创建时固定；切换不改变已有局、定时保存或经验池归属 |
| 进行中切档 | 安全暂停并确认落盘后才切；不能安全暂停的阶段明确禁止；不静默终止或继续隐性付费 |
| 多窗口与迟到响应 | 请求携带 profile/game/view 上下文与 generation；切换后旧响应不可写入当前 UI；旧 SSE 被释放 |
| 偏好 | fontScale/layout/reducedMotion 确实应用到双端；安装级 Key 不随档案变化；失败有回退说明 |
| 战绩与列表 | 正式／Mock／观战／终止／平局定义不退化；动态阵营、归档档案与恢复列表按 owner 查询 |
| 导入导出 | 20MiB 契约一致；正常往返完整；重复包提示和已结束局筛选按原方案核验，缺失则补，不静默截断 |
| 三层身份信息 | 公开事实、本人私密信息、我的推测结构独立；猜测不进入 AI prompt、公开 SSE 或判定 |
| 候选与自称 | 最多三个候选；自己为唯一角色也能记录他人自称该角色；候选池不利用隐藏真实身份 |
| 待确认旧标记 | 满字段不丢数据；编辑、保存、取消、409、刷新、显式丢弃均闭环；仅清理已确认解决的座位 |
| 历史推测与动态阵营 | 不因翻牌而静默删旧推测；旧角色转换为推测时不能凭身份名认定动态阵营，默认待观察语义 |
| 草稿与断网 | 带档案、局、视角和版本的草稿只归原上下文；未获服务端确认不得显示已持久保存 |
| 编辑完成与撤销 | 保存／清除不提交游戏行动；旧方案要求的最近一次笔记撤销需核验，不能复用游戏行动撤销 |
| 视角切换 | 玩家→上帝→玩家不残留高权限信息，不把真相自动写入个人猜测 |

待确认面板的操作应绑定创建面板时的 `gameId/profileId/seat`，不是在点击时重新读取可能已改变的当前局。对成功编辑后的待确认状态做刷新复验，避免已解决记录反复提示或覆盖用户后续判断。

保持共享标注语义，双端只实现布局差异；候选上限、规范化、冲突状态不要各复制一份。路由应继续使用已落地的有效路径，原方案示意路径与现有路径通过 API 文档解释，不为外观工作无故迁移接口。

| 局中顶栏 | 小尺寸狼冠，优先保证阶段与操作可读；不强行放大 | 桌面／手机局中截图 |
| 关于与启动展示 | 使用同源标识、统一产品名与版本；启动图不拉伸 | 应用冷启动与关于页 |
| favicon／PWA | 保留已通过的 V2 资源，验证实际浏览器书签／安装入口 | 缓存升级后的实际截图 |

建议新增生产品牌路径如 `web/assets/brand/wolf-emblem.svg`，由已交付母版派生并纳入映射表；具体路径可调整，但源码、导出器、门禁、打包清单必须同步。页面运行时不能依赖未打进包的 `design/` 目录。

大标识采用可编辑 SVG，透明贴图用于合适的展示面，应用方形图标用于 launcher；三种用途不可只拿一张带底方图到处拉伸。新增 SVG/PNG 的更新与缓存策略同样需要版本一致性。

### 12.2 FIN-09：Windows 与 Android 原生展示

- Windows：核对真正交付的是普通 Windows 目录包、Electron portable，还是两者；报告分别列出，不能拿 `app:win` 的通过证明 Electron EXE 图标已更新。
- Electron 当前 `signAndEditExecutable:false` 需专门处理资源写入链。使用已交付 ICO 或经验证同源输入；检查 EXE 内资源，而非只看 BrowserWindow 的 icon 参数。
- 验证资源管理器 EXE、实际窗口、任务栏及用户创建／固定的快捷方式；记录适用范围。不存在安装器时不伪称已经创建开始菜单入口。
- 代码签名与图标资源写入分别处理；不承诺改图标可以消除 SmartScreen 提示，不为改图标关闭不相关安全机制。
- Android：现有 legacy/adaptive/round 和启动页资源保持同源；在实际包内和设备上检查背景、裁切、耳尖／下颌、小尺寸辨认及启动图比例。
- 包验证扩展为内容校验：品牌图片、头像与其他声明交付的二进制按哈希或适当的编译产物校验方法验证，不只检查文件存在。Android 编译资源不能直接拿源 PNG 字节与编译容器硬比，应说明提取／映射方法。
- `brand:check` 覆盖母版派生关系与页面可见引用；`app:verify` 覆盖真实交付包内内容；两者不能互相代替。

## 13. FIN-10：增量渲染与连接可靠性

### 13.1 渲染与历史阅读

1. 座位以 seat 为 key 保持节点；只有座位信息、目标或标注变化时局部更新。单纯发言字块不得清空重建全部头像与座位。
2. 消息以事件 seq/稳定标识更新，流式文本更新当前消息；合并同帧刷新，避免每个字块触发完整布局。
3. 用户在底部才自动跟随；上翻时保存可见消息锚点，提示新增条数。分页／窗口化后锚点仍稳定。
4. 500 条以上历史分段加载或窗口化；保留完整回看入口，不在数据层截掉事件。测试至少包含 500、2000、6000 条事件。
5. 保存笔记、切换页签、打开抽屉和缩放不能清空草稿或抢焦点。关闭视图释放事件监听、计时器和流连接，重复进入不叠加提交。

### 13.2 连接与恢复状态

明确区分：模型思考／生成文本、等待本人、网络中断、正在重连、故障暂停、保存失败、已结束。没有可信预测时显示已耗时，不显示虚构百分比。

- 断线后按既有游标恢复；事件去重，不漏事件、不重复插入消息。玩家／上帝游标与缓存分离。
- SSE 与轮询协调，不能同时重复提交或无限叠加拉取。退避重试有上限和可见状态，用户切局后停止旧连接。
- 网络断开时禁止基于过期任务自动提交；重连后重新校验阶段、目标和服务端已接受状态。
- 模型超时／配额／Key 绑定失效分别给动作；不提供“忽略校验继续”按钮。
- 保存失败时明确“尚未保存”，安全切档／关闭依赖真正落盘结果。UI 恢复不能绕过 pending-input、终局锁或 journal 规则。
- Android 后台恢复、Windows 睡眠／唤醒和服务端重启都走真实恢复流程；禁止把断线后的空响应当作清空笔记。

### 13.3 性能验收口径

以下为施工目标，需在 FIN-00 固定设备／浏览器后测量，不是当前实测成绩。

| 指标 | 目标／验证方法 |
| --- | --- |
| 本地点击反馈 | 主操作本地反馈 p95 ≤100ms；不包括模型推理与外网耗时 |
| 本地开屏可操作 | 固定基准机热启动目标≤1.5s；冷启动单列，记录瓶颈，不伪装为同一指标 |
| 座位更新 | 连续文本流期间，未变化座位节点保持同一引用；头像不重复加载 |
| 历史滚动 | 固定发言突发输入下，用户锚点不跳到最新；窗口化不丢可访问历史 |
| 重连 | 固定断线与重启场景，恢复后事件数量／顺序与服务端一致，行动接受次数符合预期 |
| 泄漏 | 连续进入退出对局／抽屉 20 次，活跃连接及监听不线性增长，内存基线与峰值有记录 |

## 14. FIN-11：版本单一来源与构建标识

1. 建立一个明确的产品版本来源，例如拟新增的 `release-version.json`；字段可含产品语义版本与 Android build code，Git commit/build time 为构建派生信息。具体文件名在实施时确定。
2. 根包、app、desktop、Android versionName、各构建脚本及包名从该来源同步／校验，不再分别硬编码。锁文件中根包版本也保持一致。
3. Android versionCode 独立单调递增；存档 schemaVersion、导出 exportVersion、Service Worker 缓存代次不与产品版本机械绑定。
4. 下一个对外版本号由发布负责人确认；本计划不自行将版本指定为 1.5.3 或 1.6.0，也不把旧包重命名成新包。
5. 关于页、诊断、发布清单能识别产品版本、构建 commit、平台；展示信息不包含真实 Key、用户名路径或会话令牌。
6. 建议增加版本同步／版本检查命令，并在 CI 中检查：产物字段不一致即失败。这些是待新增命令，不假称当前已存在。
7. 区分产品版本与缓存内容标识：仅改 JS/CSS 即应更新对应内容哈希；不能要求人工记得升产品版本才修好缓存。

## 15. FIN-12：统一验收矩阵与证据

## 16. FIN-13：发布与回滚

1. 冻结待发布 commit，确保工作区及构建输入可追溯；先跑完整门禁和专项，再生成制品。

3. 对**最后一次构建**的确切 APK／目录包／EXE 执行内容检查，记录绝对路径、大小、SHA-256、产品版本、commit 和构建时间。

6. 回滚区分程序回滚与数据回滚：UI 回滚不得删除新档案；涉及 schema 不兼容时先使用已核验备份／迁移，不直接用旧程序覆盖新数据目录。
