## 四、纪律（每次提交都要满足）

1. 断言只收紧不放宽；新增断言必须做过**反向验证**（改坏 → 必须红 → 改回）；反向验证的"改回"**禁止用 PowerShell 文本往返**（会把 UTF-8 中文写成乱码，本项目已出过事故），用字节级读写或专用工具。
2. 每个 FIX 一个提交，可单独回滚；提交信息写明「凭什么说修好了」。
3. 判定"到底红不红"**以干净 worktree（LF，等同 CI）为准**：本机 `core.autocrlf=true` 会让本地红绿**两边都可能说谎**；按字节算哈希的守卫一律用 `git cat-file blob HEAD:<path>` 做判据。
4. 阶段收尾：干净 worktree `npm test`（当前 **681**）+ `npm run ui:check`（当前 109 项）+ `node scripts/lint.js`；`npm run gate` 已含守卫。
5. 不碰 `saves/`、正式 `config.json`、不污染 `logs/`；`output/` 下的调试产物用完即删（会让 lint 与 UTF-8 校验变红）。
6. 阶段 4（打包）**必须等用户点头**；子智能体一律**不许自己 `git commit`**，由主控逐项核验后分提交。

  2. `design/brand/v2/**` 的品牌资产 → `npm run brand:apply` 重新 pin SHA-256，再 `npm run brand:check`；
  3. `web/sw.js` 的 SHELL 清单 → 升 `VERSION` 并在 `test/sw-shell.test.js` 的 `SHELL_LEDGER` 登记新指纹。
- **断言卫生**：基线（`scripts/guards-baseline.json`）里的历史违规不阻断，**新增**才红；确有理由的例外写
  `// GUARD-ALLOW: <理由>`（同行或上一行，只写标记不生效），脚本会把所有豁免连同理由打印出来。基线收缩：`--update-baseline`。
- **紧急绕过**：`WW_SKIP_GUARD=1 git push`（打印醒目警告 + 列出要自查的三处）；只跳过全量测试：`WW_GUARD_FULL=0 git push`。
- **行尾免疫**（本机 `core.autocrlf=true` 的老坑）：守卫按 **CI 会看到的字节**复核 pin
  （`git cat-file blob HEAD:<path>`，拿不到时退回"行尾归一为 LF 的工作区"），所以 CRLF 检出不会假红；
  只提示"工作区与仓库仅行尾不同，无需重新 pin"。见根目录 `.gitattributes` 与 `test/guards.test.js`。

## 七、过程中的更正与教训（写下来是为了不再犯）

1. **我宣称修好的 P1 只修了一半**（FIX-01 → FIX-01b）：兜底查错了缓存仓，而源码注释把"已修"写得很肯定。**教训：注释里的"已修"必须有能红的断言撑着**，否则就是验收报告批评的"文档说假话"，而且是自己骗自己。
2. **本地红绿两边都可能说谎**：本机 `core.autocrlf=true`；同一个提交在 CRLF 检出上 636 中 2 红、在 LF 检出上全绿。我因此**两次**得出错误结论（一次说"两条红是我引入的"，一次说"品牌 pin 是 CRLF 哈希、CI 会红"），都是子智能体用 `git cat-file blob` 的字节证据纠正的。**教训：涉及字节/哈希的判断，一律以仓库 blob 为准**；`.gitattributes` 已从根上消除这类假红。
3. **CI 三天没真正跑过**（NEW-05）：35 次失败全是零步骤、从未分配 runner，根因是账户计费。这期间任何"CI 绿/红"都不能作为证据。**教训：门禁不可用时，本地验证标准必须顶格**（干净 worktree + 反向验证 + 断言计数核对）。
4. **子智能体反过来抓到我的洞，这才是有价值的协作**：NEW-02（状态码）、NEW-06（行尾方向）、FIX-01b（查错缓存仓）、NEW-07（别名漏检）—— 四条里有三条是"别人查我"，我要求所有交付必须带**反向验证**与**诚实边界**，正是为了这个。
