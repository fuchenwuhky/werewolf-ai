## 2. 总体设计与信息架构

### 2.1 统一产品语言

- 对用户使用“玩家档案”，不要使用“账号登录／退出登录”。切换后显示“当前档案：砚舟”。
- 使用“我的推测”“已公开信息”“仅我可见的信息”，不要把三者都叫“身份”。
- “保存标注”永远不提交游戏行动；“确认投票”才提交票；“弃票”和“跳过发言”不得共用一个模糊的“跳过”。
- 真正正常结束、玩家手动终止、故障暂停、Mock 试玩明确分开，不混成胜败。

### 2.2 页面树

```text
首页（当前档案 + 继续上局 + 开一局）
├─ 开局向导：板子 → 座位／AI 来客 → 模式与费用确认
├─ 我的对局：进行中／暂停／已结束／已归档
│  └─ 对局详情 → 时间线、结算、复盘、个人标注历史
├─ 玩家档案：新建／选择／资料／导出／归档／恢复
├─ 资料库：规则书、角色图鉴、AI 来客名册
└─ 设置：外观与操作、游戏默认偏好、模型与密钥、设备与数据、关于
```

电脑：顶部当前档案，左侧对局与座位，中央发言，右侧可收起的笔记。手机：首页底部最多 4 个入口（开始、对局、资料、我的）；局中改用专门导航，不把首页导航常驻遮住行动区。

### 2.3 局中布局

**电脑 ≥1280 CSS px**：顶部阶段／连接状态／档案；主体左座位 240px、中央内容 `minmax(420px,1fr)`、右笔记 300px；右栏可收起。1024–1279px 默认收起右栏，用抽屉，不能把三栏硬塞进去。窗口缩到 900px 以下切为紧凑布局；不能只按 User-Agent 判断。

**手机默认布局**：顶部阶段与菜单；中部“发言 / 玩家 / 笔记”页签；底部当前任务操作区。正文获得完整宽度。玩家页采用 3 列／窄屏 2 列的等宽座位卡，每卡至少 96px 高；12 人局允许正常纵向滚动，不靠把昵称缩到 10px 硬塞满屏。当前选中目标始终在行动区可见。

保留旧双列桌面为可选“紧凑桌面”，放到偏好中；仅在实际可见空间足够且触区不重叠时启用。没有跨端强行统一布局，但数据、操作名称和状态必须一致。

### 2.4 视觉规范

主题：**月夜狼冠**。狼首纹章是主要品牌符号，界面其他部分保持克制，不给每个卡片加哥特花纹。

| --- | --- |

## 3. 本机玩家档案（P0，必须优先落地）

### 3.1 功能与边界

- 首次升级创建“默认玩家”档案，展示一次迁移说明；新安装进入轻量建档，也可先使用默认档案。
- 创建：昵称 1–20 个可见字符，去首尾空白；内置头像；简介最多 100 字。允许同名，界面显示头像与最近使用时间区分，唯一身份靠 UUID，不靠昵称。
- 编辑：昵称／头像／简介；过去对局保留当时的昵称快照，不批量改历史。
- 切换：默认首页最多显示最近 4 个，完整列表可搜索。切换不更换全局 API Key。
- 归档：默认替代删除，旧战绩仍可从“已归档档案”恢复；**有未结束（进行中／待保存）对局的档案不可归档**，最后一个可用档案不可归档。
  - 契约口径（R05 登记，2026-09-23）：上面这条“有未结束局不可归档”是**比原始 §5.2 更严格的新增**，不是原计划原文 —— §5.2 禁止的只是“进入回收站”。之所以收紧：归档会让档案从选择器里消失，那局就再也回不到任何档案名下（静默丢失归属）。
  - **最终判定在服务端**（`PATCH /api/profiles/:id {archive:true}` → 400 + 可读原因），前端 `archiveBlockReason()` 只是预检；服务端的“未结束局计数”是**内存 ∪ 磁盘**（服务重启后仅存于存档的局也算），读不出的坏档按保守拒绝处理。
  - 归档的“判定 + 写盘”与建局／开始共用**同一档案级串行周期**（`ProfileStore._serialize`），所以并发建局时不会出现“先归档成功、后建出一局无归属的未结束局”。这两条不变量由 `test/r05-archive-contract.test.js` 钉住。
  - “最后一个可用档案不可归档”仍由**前端**判定：它约束的是选择器（本机还有没有别的档案可选），不涉及数据归属；服务端不拦，以免同一条规则出现两套互相矛盾的定义。
- 删除：仅在归档管理中二次确认；明示涉及局数与笔记数，建议先导出，先移入回收区 30 天。正在运行／待保存的对局所属档案不能删除。
- 导入导出：只做用户主动文件操作，不联网。第一期导出资料、偏好、已结束对局、笔记和统计依据；进行中对局只显示“未纳入可迁移包”，不要导出成可直接运行的会话。
- 这些是共用设备上的数据分类，不是密码保护。同一系统用户能读本地文件或管理服务，就可能访问其他档案；界面与文档都必须说明。

“本机”的边界是同一个安装／数据目录：电脑 Electron 与手机独立 APK 各有自己的档案，不会自动互通，可由用户手动导入导出。手机浏览器若通过既有局域网配对访问电脑服务，读的是电脑那一份资料，这是同一服务的访问，不是新增云同步。回收区到期清理应明确提示并经用户确认，本期不后台静默永久删除。

### 3.2 资料归属矩阵

| 数据 | 所属与规则 |
| --- | --- |
| 昵称／头像／简介／游戏默认偏好 | 档案级 |
| 历史对局、当前对局恢复入口、成绩与笔记 | 档案级；对局创建时锁定归属 |
| 字号、音效、减少动态、常用布局 | 档案级偏好；设备安全区／窗口尺寸仍是设备级 |
| API 地址、API Keys、绑定状态、连接配置、LAN 配对 | 安装级；标出“此设备共享”，不随切换变化、不包含在档案导出 |
| AI 角色复盘经验池 | 默认档案级，不能通过当前选中档案错误写入；旧池归属默认档案，不静默共享给新档案 |
| 公共规则、板子模板、AI 名册与软件资源 | 安装级只读 |
| 观战局／Mock 局 | 可归档，但不进入个人正式胜率；明确分类 |

### 3.3 存储决策：继续零运行时依赖

第一期沿用 JSON 与现有原子写，不引入数据库／ORM。新增独立 Store，**不要向 `src/api.js` 再堆存储逻辑**。

```text
WW_DATA_DIR/
  config.json                         # 原有安装级配置，不搬密钥
  profiles/
    index.json                        # {schemaVersion, revision, profiles:[...]}
    <profileId>/
      profile.json                    # 资料与偏好
      annotations/<gameId>.json        # 私人笔记，独立 revision
      experiences.json                # 本档案 AI 复盘经验
    trash/<archiveId>/                # 归档删除回收，保留恢复清单
  saves/<gameId>.json                  # 原路径保留，新增归属元数据
  saves/journal/...                   # 沿用现有 journal，不由当前档案改变路径
  migrations/profiles-v1.json         # 迁移游标／已完成项／失败项
```

`profileId` 使用随机 UUID；`gameId`、`profileId` 都先白名单校验再拼路径。写入用临时文件→原子替换、按资源排队；失败不得提前向 UI 返回已保存。并发编辑带 `revision`，过期写返回 409。应用崩溃后可重跑迁移，不能复制出两个默认档案。

建议数据契约（字段名为施工约定，不表示当前已实现）：

```json
{
  "schemaVersion": 1,
  "id": "UUID",
  "nickname": "砚舟",
  "avatarId": "scholar",
  "bio": "",
  "preferences": {"fontScale": 1, "layout": "reading", "reducedMotion": false},
  "createdAt": "ISO8601",
  "updatedAt": "ISO8601",
  "archivedAt": null,
  "revision": 1
}
```

存档包装层增加 `ownerProfileId`、`ownerNicknameSnapshot`、`ownerHumanSeat`、`profileSchemaVersion`；所有存盘／恢复／锚点重建／重新启动／终局／补写都必须保留这些字段。**不从全局的“当前档案”推导存盘归属。**

### 3.4 “当前档案”与进行中对局

1. 当前选择属于各个客户端／窗口，不设置一个所有设备共用的 `api.activeProfileId`。
2. 非游戏资料请求明确携带档案 ID；游戏请求以创建时的不可变归属为准。选择档案不是认证，原有管理权限、来源校验、对局令牌不能省略。
3. 窗口 A 使用档案 A、窗口 B 使用档案 B 时，两局互不改归属。异步 AI 回调／定时存盘只引用所属 entry。
4. 正在对局时切换，要显示“留在本局”与“保存并暂停后切换”。仅在引擎安全暂停、待决策处理完毕且落盘成功后允许切换。
5. 如果某阶段无法可靠暂停，本期明确禁止切换并说明原因，不能隐式终止、丢弃进行中的行动或让 AI 默默继续付费运行。
6. 切换时取消当前页 SSE／轮询、清空旧视图缓存、再加载新档案；过期网络响应以请求 generation 丢弃，不能出现 A 的笔记闪到 B 页面。
7. `lastProfileId` 可作为下次默认偏好；数据本体必须在服务端。Electron 端口变动后仍能读取资料。

### 3.5 旧数据迁移与导出

迁移顺序：完整备份 → 建默认档案 → 为无归属存档打标 → 迁移经验池 → 建索引 → 单次提示完成。每一步记录进度与旧文件校验，出错留在可读兼容模式，不删源文件。

旧笔记：只能从**实际可访问的旧 origin** 读取 `ww_tags_*`、`mww_tags_*`。两者一致则去重；同座位冲突且没有时间戳时，保留为两个候选并提示确认，不能伪造“较新”的一条。旧值映射成 `candidateRoleIds:[roleId]`、`leaning:unknown`，不要凭角色硬推动态阵营。迁移后写服务器成功才登记完成。

特别限制：Electron 曾使用随机端口，旧 origin 的 localStorage 不一定可访问；不可声称全部旧笔记都能自动找回。能打开旧实例时提供“导出旧笔记”，否则说明限制，**不要递归扫描用户浏览器所有个人数据**。

导出包为版本化 JSON，包含 `manifest`、档案、笔记与允许导出的结束局；不含密钥、playerToken、godToken、管理 Cookie、原始请求头、内部锚点或决策 journal。第一期导出局为可读回放，不承诺恢复运行。默认限制 20 MiB，超限允许按时间／局数分包，不静默截断。

导入前预览档案名／对局数／来源版本；校验大小、类型、字段、文件关系、游戏结束状态，拒绝未知未来主版本。新建档案导入时重新映射 profileId 与冲突 gameId，并同步改笔记引用；不信任包里的任意磁盘路径。重复包以 packageId＋内容哈希提示跳过；任何验证失败都不部分覆盖现有档案。

### 3.6 计划新增 API

| 接口 | 约定 |
| --- | --- |
| `GET /api/profiles` | 有管理权限才返回档案列表，不回传密钥或会话 |
| `POST /api/profiles` | 昵称／内置头像／简介，服务端生成 UUID |
| `PATCH /api/profiles/:id` | `expectedRevision`；支持资料、偏好、归档／恢复，字段白名单 |
| `DELETE /api/profiles/:id` | 归档后才允许，移入回收区；活动局／最后档案拒绝 |
| `GET /api/profiles/:id/stats` | 仅本档案，正式／试玩／观战／终止分桶 |
| `GET /api/profiles/:id/games` | 仅本档案，分页／筛选，不泄露别档案行 |
| `GET /api/profiles/:id/export` | 指定结束局范围，生成脱敏的版本化包 |
| `POST /api/profiles/import/preview` | 校验并显示计划，不写数据 |
| `POST /api/profiles/import` | 再校验，事务式落地；可重试不重复 |
| `POST /api/games`（扩展） | 新客户端必须发送合法 `profileId`，开局时固化归属 |

旧客户端兼容期：只有迁移标记允许的本机旧客户端缺省到默认档案，并记录弃用日志；新客户端缺 ID 应 400，不静默归入别人的档案。查询任意 ID 不代表授权。所有管理与修改接口复用既有门禁、限流、来源校验。

### 3.7 个人战绩定义

胜率分母只包含本人参与、真实模式、自然结束且可判定胜负的对局。Mock、纯观战、手动终止、未结束分别计数；平局单列，不算胜或负。个人胜负使用已有 `game.factionOf()`／评分结果的有效阵营，不按角色名称猜，暗恋者等动态阵营必须覆盖。

## 4. 对局身份标注 V2（P0）

### 4.1 三层信息不能混用

| 层 | 来源 | 展示 | 能否编辑 |
| --- | --- | --- | --- |
| 已公开信息 | 该视角有权读取的公开事件／公开翻牌 | `✓ 已公开：狼人`，实线、文字清楚 | 不能 |
| 仅我可见的信息 | 当前玩家本人有权读取的技能结果／身份／狼队信息 | `仅我可见`，单独区域 | 不能 |
| 我的推测 | 当前档案主动填写的标注 | `? 偏狼 · 候选：狼人/狼王`，问号与虚线 | 能 |

死亡不等于公开身份；“别人自称预言家”不等于“已经确认预言家”。猜测即使与公开事实冲突，也要作为历史记录保留，显示“与已公开信息不符”，不静默删除。

### 4.2 一张标注包含什么

- 倾向：待观察／偏好／偏狼／第三方可能，默认待观察。
- 候选身份：最多 3 个，可清空。候选池来自本局板子，不读取隐藏真实身份。
- 玩家自称：可记 1 个自称角色、来源轮次，**不因自己已占唯一身份而禁止记录其自称**。
- 把握：低／中／高，定性主观值，不显示假精确“87% 概率”。
- 依据：最多 200 字，可选关联一个当前视角可见事件的 seq。
- 时间：第几天、阶段、更新时间；支持撤销最近一次保存和清除当前标注。

```json
{
  "schemaVersion": 2,
  "profileId": "UUID",
  "gameId": "game-id",
  "revision": 3,
  "seats": {
    "7": {
      "leaning": "wolf",
      "candidateRoleIds": ["wolf", "wolfking"],
      "claimedRoleId": null,
      "confidence": "medium",
      "note": "对 2 号的立场前后变化，需要回看",
      "evidenceSeq": 45,
      "day": 2,
      "phase": "speech",
      "updatedAt": "ISO8601"
    }
  }
}
```

数据在独立 AnnotationStore 中，不进入 `Game.players`、引擎事件、AI system prompt、公开 SSE 或其他档案导出。传给笔记 UI 的公开事实仍经过已有视角裁剪。

### 4.3 电脑交互

- 点座位：只选择当前行动目标或打开玩家信息，不直接投票。
- 每位玩家提供常显笔记入口，40px 可点击方框；不能只在 hover 出现。
- 右侧固定笔记面板／小窗口抽屉编辑；保存后局部刷新，不重绘整桌。
- 不把笔记按钮嵌套进另一个 button；目标选择与笔记按钮是兄弟节点，并明确阻止冒泡误选。
- 键盘 Tab 可到达，Enter/Space 激活；Esc 关闭抽屉，焦点回到来源；输入框内不拦截数字快捷键。

### 4.4 手机交互

- 玩家卡内有“笔记”入口；点目标主体只选人，底部显示“目标：7号 · 终章”。
- 非目标阶段可点卡片查看详情，再点“编辑笔记”。长按仅作可选快捷操作，不能是唯一入口。
- 笔记采用底部面板，最大高度 `min(85dvh, 可见键盘上方高度)`；内容滚动，保存／取消保留可见。
- 关闭时有未保存更改：提供继续编辑／放弃；保存失败保留草稿。
- 标注状态在玩家页、目标选择器和笔记列表一致；不靠手机侧边一个 11px 的“🏷”传递具体信息。
- 本人角色不需要标“推测”；已死亡玩家仍可补充历史依据，但不能成为非法行动目标。

### 4.5 持久化、视角与冲突

`GET/PUT /api/profiles/:profileId/games/:gameId/annotations`，PUT 使用 `expectedRevision` 与 `schemaVersion`。受已有管理权限和本档案对局归属校验；注释能力不授予额外游戏权限。对新旧 API 的授权组合加集成测试。

共享 `web/shared/annotations-model.js` 负责白名单、规范化、展示语义；`annotations-view.js` 负责可复用控件；两端只处理布局适配。别再分别复制业务判断。

并发冲突返回 409：提示“另一窗口更新了笔记”，可重新加载或人工合并；不能最后写入者无提示覆盖。离线先保存带 profileId/gameId 的本地草稿，恢复时对 revision 进行冲突检查。动态端口导致草稿失效的可能性必须通过“服务器未确认保存”状态提示，不能称已持久保存。

上帝／纯观战视角显示真实信息；**禁止把真实身份自动写回个人猜测**。从观战切回玩家，重新获取该视角视图、清空高权限缓存。笔记只能关联该玩家确实看得见的事件 seq；不得从 event ID 旁路获取私密内容。

## 5. 按钮、触区与输入规范（P0）

所有尺寸为 Web CSS px，Android 原生 dp 另按平台实现；不要将 CSS px 与物理像素混用。

| 控件 | 电脑默认 | 手机／粗指针 | 其他约束 |
| --- | --- | --- | --- |
| 核心行动：开始、发言、投票、技能确认 | 高 44，最小宽 112 | 高 52，优先占可用主宽度 | 只有一个主操作；选中目标与动作写清 |
| 常规按钮／输入框／下拉 | 高 40 | 高 48 | 输入字体手机 ≥16；label 可点 |
| 纯图标：设置、关闭、笔记、返回 | 40×40 | 48×48 | 图形 20–24，不拉大到满框；有 aria-label |
| 桌面紧凑工具按钮 | 最小 32×32 | 提升为 48×48 | 不用于投票等主要动作 |
| 倾向、候选身份 chip | 高 36–40 | 高 44–48 | 文字不可截断成无法识别；有 aria-pressed |
| 座位／玩家卡点击区 | 至少 64×72 | 至少 96×96 | 整卡目标区与独立笔记区不重叠 |
| 人数加减／分页 | 40×40 | 48×48 | 相邻至少 8px；到上限禁用并说明 |
| 多选／开关／单选 | 整行 ≥40 高 | 整行 ≥48 高 | 标签也是命中区；不得只点 16px 方框 |
| 列表行：档案、存档、菜单 | ≥48 高 | ≥56 高 | 行尾危险按钮独立，不能误触进入详情 |

项目将手机主触区定为 48px 是产品选择；WCAG 2.2 的最小目标标准是 24×24 CSS px（含例外），增强标准是 44×44。不能把 48px 误写成 WCAG 的统一法定要求。[W3C 最小目标](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[W3C 增强目标](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)。

统一实现：新增 `--control-height-*`、`--touch-min`、`--control-gap`，用组件 class 控制；清理 `.tag-btn` 中强制 20px 的 `!important`。通过 `@media (pointer: coarse)` 支持触屏电脑，不只按屏宽判断。透明扩展命中区不能与别的控件重叠。

必备状态：默认、hover、focus-visible、选中、禁用、处理中、成功、失败。禁用必须提供邻近原因文字；处理中保留原宽度并防重复提交；失败不清空输入。Enter 发送／Shift+Enter 换行作为可选偏好，中文输入法 composing 期间不得发送。

危险操作：终止本局、清空资料、删除档案独立于主按钮至少 16px；二次确认写明对象和影响，不使用纯图标删除。发言跳过／弃票保留一次撤销提示仅适用于本地未提交选择，**已被服务端接受的游戏行动不提供假撤销**。

## 6. 手机端整体优化（P1）

1. 首页：当前档案卡、继续上局、开始新局作为前三项；API 详细配置收进设置，初次可使用醒目的 Mock 试玩。
2. 开局向导：板子简介／人数校验 → 座位与 AI 来客 → 真实／试玩确认。记住档案偏好，但模式要持续可见，不能用颜色暗示是否收费。
3. 对局主视图：第 2.3 节的阅读布局；玩家列表滚动位置、当前发言定位、手动翻看历史位置都能保留。
4. 行动区：固定在可视区底部，包含当前任务、已选目标、主按钮。支持 `env(safe-area-inset-bottom)` 和 `dvh`；软键盘弹出时不遮发送按钮，不让正文跳回最新。
5. 选人：候选列表中显示座位、头像、昵称、存活、当前个人标注；非法目标不可选并有原因；选择和确认分两步。
6. 弹层：普通确认居中，长表单底部面板；只允许一个最上层模态，背景 inert／不可滚动；系统返回先关弹层，再回页，最后询问离开对局。
7. 结算：先给结果、本人角色／阵营、得分依据与关键行动；再看全员真相、时间线和 AI 复盘。长内容折叠，复盘失败可重试且不重复扣费提交。
8. 设置：说明安装级／档案级；音效默认不在系统静音时强制播放；手机备份通过系统文件选择／分享能力完成，不能依赖桌面路径输入。
9. 去掉限制用户缩放的 `maximum-scale=1/user-scalable=no`，检查放大后布局；300% 极端场景允许重排，不以缩小正文补救。

## 7. 电脑端整体优化（P1）

1. 首页不再把所有 API 参数和玩法设置铺成一整页表单；保留快速开局，把高级模型配置分组折叠。
2. 左侧座位提供圆桌／列表切换；默认列表更适合标注，圆桌保留氛围；12 人以上或小窗口自动提示列表，不强制缩小字。
3. 右侧笔记与时间线可切换、可收起；可拖动宽度但必须有键盘可用的恢复默认入口。
4. 发言区支持按天／阶段导航、仅看公开／本人可见过滤；过滤不改变后端权限。新消息不抢滚动，提供“有 N 条新发言”。
5. 对局列表具备档案筛选、模式标识、暂停原因、最后保存时间；恢复前显示执行模式和模型快照，不能让用户以为旧局会无条件用当前设置。
6. Electron 记住窗口大小与位置时校验屏幕边界；支持 100/125/150/200% 缩放，窗口缩小改布局；快捷键菜单有说明，不与文本编辑冲突。
7. 断网／模型不可用／配额／密钥绑定失效／存盘失败区分提示；提供针对性动作，而不是全部报“请求失败”。安全错误不可提供“忽略验证继续”。

## 8. 性能、可靠性与可访问性（P1）

- 座位按 seat key 增量更新，头像只在映射变动时换 src；不要每次流式字块都清空重建全桌。
- 发言采用增量追加与节流渲染；上翻阅读锁定滚动；长局达到 500 条后分段加载或窗口化，保留可访问的历史入口，不直接丢记录。
- UI 状态必须区分模型思考、生成文本、等待本人、暂停、保存重试。没有可信估算时只显示已耗时，不伪造进度百分比。
- 模型失败、SSE 断线、磁盘错误、后台挂起分别演练；沿用既有恢复策略，不能因换 UI 绕开 pending-input、终局锁或保存重试。
- 键盘焦点可见、Tab 顺序符合视觉；模态进入设焦点、关闭还原；屏幕阅读器能读“7号终章、我的推测偏狼、尚未选中”。
- 不用颜色作为唯一状态；正文对比目标 4.5:1，大字号与图形按适用标准分别核验；减少动态时关闭脉冲与大范围位移。
- 交互本地反馈目标 ≤100ms，局域静态界面开屏可用目标 ≤1.5s（约定基准机／网络后测量）；不将 LLM 回答速度作为纯前端性能指标。
- 公共资料只缓存静态资源；档案、笔记、游戏权限视图不混入公共 Service Worker 缓存。切档缓存键至少含安装标识＋profileId＋gameId＋视角。

### 推荐顺序与阶段交付

1. M0：固化基线＋触区规范＋数据模型。先评审 ProfileStore 与笔记 schema。
2. M1：档案能创建切换、旧数据迁移、归属与统计正确。此时 UI 可以朴素，但不能串档。
3. M2：笔记模型与两端编辑全通，标注／选人不冲突、AI 完全不读笔记。
4. M3：双端布局、设置、开局／复盘、品牌替换完成，进入全矩阵测试。
5. M4：安装包、迁移回滚与升级文档验收。不能把截图完成当作功能完成。

每个工作包单独提交或可独立回滚的提交组；提交说明必须包含任务编号、变更文件、测试、兼容性与未完成项。界面骨架可并行施工，不能在数据契约未确定时各自造一套接口。

## 14. 风险与回滚规则

- 数据迁移优先 sidecar／包装层元数据，不批量重写引擎事件与 journal。旧版程序不认识新字段的情况必须实测，而非假定安全。
- 档案切换与暂停是最高风险交界，安全暂停没完成就先禁用切换，不为追求“一键”牺牲存盘。
- 独立客户端当前档案、不可变对局 owner、带 owner 的异步回调，是防串档的三道约束，缺一不可。
- 原有密钥绑定、配置失效关闭策略、局域网管理认证、视角裁剪与补写链均列回归，严禁以新 UI 为由绕过。
- UI 回滚不删除档案／笔记新数据；数据格式回滚必须先恢复备份或跑已验证的逆迁移，不直接用旧版覆盖新数据目录。
- 图标独立提交，若品牌接入失败可回滚静态资产和缓存版本，不阻断核心数据恢复。
- 真实 LLM 性格表现、回复质量和费用不在本轮 Mock 验证的结论内。需要真实试局时另经用户同意预算与数据范围。
