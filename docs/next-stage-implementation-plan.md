# AI 狼人杀下一阶段施工计划书

> 计划类型：可直接交给施工 AI 执行  
> 本轮范围：本机玩家档案、电脑/手机双端 UI、性能与稳定性  
> 不在本轮：新玩法、新角色、云账号、密码、在线匹配、付费与社交系统  
> 编制基线：`81023b0`；施工开始前必须以实际 `HEAD`、工作区和 `docs/fix-plan-2026-09-21.md` 为准重新登记

## 1. 目标与不可变边界

本轮把软件从“功能已经具备”提升为“档案归属清楚、双端操作顺畅、视觉统一、恢复可靠、安装包可信”的可交付产品。实施顺序固定为：

1. 收齐当前返修，冻结数据安全基线。
2. 完成本机玩家中心、双端首页与玩家自定义头像。
3. 完成三步开局、局中布局、身份标注和结算体验。
4. 完成性能、断线恢复、原生文件导出和三种制品验收。

产品边界：

- “账号”在产品文案中统一称为“玩家档案”：仅本机多档案，不增加注册、密码和云同步。
- 档案是资料归属机制，不宣称具备不同使用者之间的安全隔离能力。
- API 地址、模型和密钥属于设备级设置，切换档案不切换密钥。
- 保留现有狼首品牌、AI 头像、昵称、性格库和游戏引擎。
- 玩家头像支持 **8 款内置头像＋玩家上传自己的本地头像**；自定义图片只保存在本机，不联网处理。
- 沿用原生 JavaScript/CSS、Node 服务端和 JSON 存储，不更换框架或数据库。
- 本轮不开发新玩法。新手教学、挑战模式、新角色进入下一期候选，不得挤占本轮验收时间。

## 2. 批次与验收闸门

每批必须是可运行、可回滚、可单独验收的小交付，不允许全部改完后一次性交差。

| 批次 | 工作内容 | 完成标准 |
| --- | --- | --- |
| M0 | 当前返修收口、工作区交接、基线冻结 | 现有改动归属明确；数据风险项关闭；全量门禁可复现 |
| M1 | 视觉 token、共享状态、基础控件、自定义头像数据层 | 双端代表页面可演示；头像上传/回退/迁移单测通过 |
| M2 | 玩家中心、切档、战绩、数据管理 | A/B 两档案全流程正确；浏览器、EXE、APK 均能导出再导入 |
| M3 | 双端首页与三步开局 | 最终确认前不建局；连点不重复；归属和模式不可漂移 |

## 3. 视觉系统与前端组织

视觉方向固定为“月夜集会、狼冠纹章、克制的暗黑哥特”。狼首承担品牌识别，发言和笔记区域优先保证长时间阅读，不堆叠无意义装饰。

| 语义 | 色值 |
| --- | --- |
| 页面背景 | `#06090F` |
| 内容面板 | `#0F1626` |
| 正文骨白 | `#EBE4D7` |
| 主操作古金 | `#D8B25F` |
| 焦点/月光 | `#DBE6FF` |
| 危险/狼性 | `#B3323F` |

实施要求：

- 沿用本地衬线标题字体栈、系统无衬线正文字体和等宽数据字体，不增加外部字体依赖。
- 桌面正文默认 14px，手机正文默认 16px；辅助文字默认不低于 12px；手机输入框不低于 16px。
- 手机常用触区至少 48×48px，主要确认按钮高 52px；桌面普通按钮至少 40px，主要按钮至少 44px。
- 缩小字号或启用紧凑布局不得缩小最低触区。
- 提供正常、悬停、键盘焦点、选中、禁用、加载和错误状态；危险操作不能只靠红色表达。
- 核心导航和操作图标使用统一 SVG；不要全局删除聊天内容或玩家姓名里的正常 emoji。
- “减少动态效果”同时作用于两端，关闭持续氛围动画和非必要过渡。
- 优先复用共享标注模型和会话模型；新增共享的档案状态、开局草稿、连接状态模块。两端只保留布局和输入适配差异。
- 不通过不断追加高特异性选择器和 `!important` 叠补丁。新模块验收后删除被替代的旧入口、样式和重复事件绑定。

M1 至少提供 1440×900、390×844 的首页、玩家中心、局中代表截图，并额外检查 320×568 小屏。

## 4. 玩家头像：内置与本地自定义

### 4.1 用户体验

档案编辑页提供两个分区：

1. 内置头像：继续支持现有 `scholar / hunter / seer / wolf / witch / night / candle / mask` 八个 ID，并为其使用统一风格的 SVG 徽记。
2. 自定义头像：允许玩家从设备选择 PNG、JPEG 或 WebP 图片，在本地裁切后保存。

自定义流程固定为：

- 选择图片后打开方形裁切页，支持拖动和缩放，实时预览圆形与方形两种显示结果。
- 客户端先检查原始文件不超过 10MiB、可成功解码、宽高均不超过 8192px。
- 使用 Canvas 按“居中覆盖”裁成 512×512，并重新编码为 PNG；重新编码会移除 EXIF、位置等原始元数据。
- 上传后的 PNG 不得超过 2MiB；超限时给出“请选择更简单的图片或重新裁切”，不自动降低到不可控画质。
- 保存自定义头像后立即更新当前档案、首页、顶栏和玩家中心；正在进行的对局 owner 昵称不变，头像只按当前档案展示。
- 提供“改用内置头像”和“删除自定义头像”两个明确操作。删除后回退到档案当前 `avatarId`，不回退为破图。
- 图片加载、解码、写盘失败时保留原头像；不能先清空再上传。

### 4.2 存储与兼容

保留现有 `avatarId` 作为内置头像和错误回退，不更改旧档案数据。`profile.json` 增加可选字段：

```json
{
  "avatarId": "scholar",
  "customAvatar": {
    "version": 1,
    "mime": "image/png",
    "bytes": 123456,
    "sha256": "64位小写十六进制",
    "updatedAt": "ISO-8601"
  }
}
```

二进制固定存为 `profiles/<profileId>/avatar.png`，不得保存用户原始图片。旧档案缺少 `customAvatar` 时完全按 `avatarId` 工作，无需迁移。

头像写入必须使用同目录临时文件、校验完成后原子替换：先写新文件，再更新 `profile.json`；任一步失败均保留旧文件和旧元数据。切回内置头像时先原子更新档案元数据，之后再清理不再引用的图片；清理失败只记录可恢复告警，不让资料更新失败。

归档、回收站恢复和删除沿用整个档案目录移动，自定义头像必须随档案一起移动。临时头像文件进入现有陈旧临时文件清理规则。

### 4.3 头像接口

新增窄接口，继续遵循管理会话、可信 Origin、限流和 `expectedRevision` 规则：

| 接口 | 输入 | 成功响应 |
| --- | --- | --- |
| `PUT /api/profiles/:id/avatar` | `Content-Type: image/png`；原始 PNG body；`X-Profile-Revision` | `{ profile, avatarUrl }` |
| `DELETE /api/profiles/:id/avatar` | `X-Profile-Revision` | `{ profile, avatarUrl }` |
| `GET /api/profiles/:id/avatar?v=<sha256>` | 无 body | PNG 字节、强 ETag、私有缓存 |

服务端不信任文件扩展名，必须检查：

- Content-Type 精确为 `image/png`。
- body 大于 0 且不超过 2MiB。
- PNG 签名正确，IHDR 存在，宽高精确为 512×512。
- 只接受常见 8-bit RGB/RGBA 色彩类型；拒绝畸形、截断和无法完整读取的文件。
- 计算 SHA-256 后再落盘；URL 使用内容哈希避免旧头像缓存。

`GET` 仅服务于本机管理会话。找不到或损坏时返回明确 404/500，由 UI 使用 `avatarId` 备用图；不能返回 HTML 伪装成图片。

### 4.4 导入导出

档案导出包增加可选字段：

```json
{
  "profile": {
    "customAvatar": {
      "mime": "image/png",
      "sha256": "...",
      "dataBase64": "..."
    }
  }
}
```

- 自定义头像计入现有 20MiB 导入导出总上限。
- 导出前重新计算文件哈希并与元数据核对；文件丢失或损坏时导出失败并指出头像问题，不能静默导出一份看似完整的包。
- 导入先验证 Base64、字节上限、PNG 结构、尺寸和哈希，再开始任何写盘。
- 导入仍创建新 UUID；头像写入新档案目录。任一步失败参与整次导入回滚与恢复记录。
- 不包含用户原始文件名、原始 EXIF 和本机绝对路径。

## 5. 玩家中心

手机“我的”必须成为独立页面，不再只打开管理弹层；桌面首页与顶栏提供一致入口。页面固定为四组：

1. 个人资料：头像、昵称、简介、当前档案。
2. 对局与战绩：进行中、最近完成和统计概览。
3. 外观与操作：字号、阅读布局、减少动态效果。
4. 数据管理：导出、导入、归档、回收站和待清理恢复记录。

### 5.1 档案选择

- 启动时优先使用本地保存且仍有效的档案。
- 本地选择失效时，依次选择服务端最近使用档案、有效默认档案、其余可用档案。
- 以 UUID 判断身份，允许昵称重名。
- 新建后先加载完整档案再选用，不得把尚未进入缓存的 ID 设置为当前档案。
- `lastUsedAt` 由真实选用或开局更新，不能用资料编辑时间冒充。
- 首次启动保留自动创建的默认档案，用非阻断提示引导改名、换头像，不增加注册页。

### 5.2 切档与并发

- 同源桌面/手机页面使用同一当前档案键，并监听跨窗口变化。
- 切档后立即撤下旧档案战绩和对局内容，显示加载状态。
- 异步请求绑定发起时的 `profileId` 与请求代次；迟到响应不得覆盖新档案页面。
- 当前浏览档案可变化，但进行中对局的 owner、笔记、经验和战绩始终固定。
- 本窗口有未保存资料或笔记时，切档先确认；其他窗口切档不能直接销毁当前草稿。
- 有未结束对局的 owner 档案不可进入回收站；返回明确阻止原因，不得悄悄终止对局。

### 5.3 偏好与统计

- 同一档案的偏好写入串行化，合并尚未发送的连续修改。
- 409 后重读服务端版本：无冲突字段合并后重试一次；同字段冲突保留草稿并由用户选择。
- 请求完成时若已切档，只更新原档案缓存，不改变当前页面。
- 昵称统一遵循服务端 20 字符限制，简介沿用 100 字符；长昵称可省略展示，但详情可读完整内容。
- 展示正式局胜、负、平／不可判定，以及试玩、观战、终止分桶。胜率分母为有效胜负局，分母为零显示“暂无”。
- 本轮不增加段位、排行榜、成就和趋势图。

## 6. 必要接口扩展

现有 profiles CRUD、统计、对局列表、标注和恢复接口优先复用。除第 4 节头像接口外，仅允许以下扩展：

| 接口 | 变更 |
| --- | --- |
| `POST /api/profiles/:id/touch` | 记录真实最近使用；不制造资料编辑 revision 冲突 |
| `GET /api/profiles/:id/games` | 增加可选 `status`、`offset`、`limit`；旧的无参数调用保持兼容 |
| `GET /api/profiles/:id/games/:gameId/history` | 已结束对局只读历史，按事件游标分页，不启动引擎或模型 |
| 对局 view 的 `pending` | 增加当前任务唯一 `pendingId` |
| `POST /api/games/:id/action` | 新客户端必须提交 `pendingId`，校验并防止重复应用 |

接口规则：

- 对局列表默认每页 30、上限 100；分页响应含 `rows / total / hasMore`。
- 筛选只支持 `all / unfinished / finished`；合并内存和磁盘记录，同一 gameId 只出现一次，状态以内存为准。
- 日期统一解析为时间值排序，不直接比较混合数字和 ISO 字符串。
- 列表只返回公开摘要，不含令牌、隐藏身份、密钥和 AI 内部上下文。
- 历史接口验证档案与对局归属，只允许已结束局；事件默认 100、上限 200 条一批。
- 损坏数据返回明确错误，不能伪装成空列表。

## 7. 数据导入导出与原生保存

- 保持“导入创建新档案、重映射 gameId”的契约，不覆盖原档案。
- 保持 20MiB 包上限，并验证近上限真实文件可完成预览和导入。
- 导出范围明确为档案资料、自定义头像、已结束对局和笔记；进行中对局不进入导出包。
- 不导出密钥、令牌、Cookie、日志凭证和恢复锚点。
- 笔记文件缺失可表示无笔记；文件损坏或读取错误不能静默当作无笔记。
- 导入成功数量来自完成落盘的数据；失败走现有事务回滚和恢复记录。

三种运行环境必须分别验收真实文件保存：

- 浏览器：同源下载，UI 只提示“已发起下载”，未经确认不宣称保存成功。
- Electron：通过受限 preload 接口 `exportProfile(profileId)` 调用主进程；主进程自行构造本机同源 URL 并使用保存流程。继续拒绝任意新窗口、任意外部 URL 和任意路径。
- Android：通过原生桥接和系统“创建文档”流程保存 JSON；不要把 20MiB 数据整体塞进 JS bridge。只允许导出本机服务的档案路径。

三个适配器统一区分保存完成、用户取消和失败。最终验收必须从实际保存位置选择该文件并成功导入。

## 8. 首页与三步开局

### 8.1 首页

- 桌面：首页主要区域只放品牌与当前玩家、继续上局、开始新局；历史、资料和设置为次级入口。
- 手机：保持“开始、对局、资料、我的”四个主入口，各自对应独立页面。
- 无可恢复局时显示简洁空状态，不保留无意义恢复按钮。
- API 长表单不占首页；设置中明确区分档案偏好与设备配置。
- “试玩”注明使用流程脚本、不调用模型，不能暗示已经体验真实 AI 推理。

### 8.2 开局步骤

| 步骤 | 内容 |
| --- | --- |
| 1. 板子与规则 | 模板、人数、身份组成、板规；高级选项默认折叠 |
| 2. 参与与座位 | 玩家/观战、昵称、固定/随机座位、AI 来客说明 |
| 3. 确认开局 | 档案、板子、人数、座位策略、试玩/真实、模型配置状态 |

- AI 阵容继续按现有机制开局分配；没有准确预选能力时不得展示伪造的确定阵容。
- 新草稿默认试玩；恢复既有草稿或对局时保持原模式，不能静默切换。
- 草稿按档案保存到会话存储，不含密钥、令牌；切档不继承上一档案草稿。
- 后退保留内容；第三步前不得调用建局 API。
- 最终提交冻结档案与全部参数，并设置单次提交锁。
- 建局结果不明时先查询已有对局，禁止盲目自动重建。
- 缺 Key、绑定失效、板子非法时显示具体原因和修复入口；不得静默降级为试玩。
- 返回首页不等于终止，终止始终为独立危险操作。

## 9. 局中 UI、身份标注与笔记

### 9.1 响应式布局

桌面：

- ≥1280px：玩家列表 240px、发言弹性区、笔记 320px。
- 960—1279px：玩家列表与发言双栏，笔记使用抽屉。
- <960px：发言主视图，玩家和笔记分别作为抽屉。
- 默认列表座位视图；圆桌只在空间足够时作为可选展示，不通过压缩头像和按钮适配窄屏。

手机：

- 局中使用“发言、玩家、笔记”导航；首页四项底栏不得叠加。
- 底部行动区只承载当前任务，预留安全区与键盘空间。
- 键盘弹起后输入、错误提示和提交按钮都能滚动到达。
- Android 返回依次关闭最上层弹层、返回发言页、询问离局；一次只处理一层。

### 9.2 身份信息三层语义

1. 系统事实：当前视角已经获知的身份或状态。
2. 玩家自称：明确标注“自称”，不得当作系统确认。
3. 我的推测：候选身份、阵营倾向、把握程度和私人备注。

三层必须有文字标签，不能只靠颜色。玩家视角不得从上帝数据、缓存或头像提示泄漏未公开身份。

### 9.3 笔记

- 沿用最多 3 个候选、200 字备注和单条证据定位的现有模型。
- 自称角色覆盖当前板子的完整角色池，允许记录对跳。
- 清除使用 DELETE；空占位不计入导出数量。
- 保存失败保留草稿；409 同时展示服务端和本地内容，不自动覆盖。
- 草稿按 owner、gameId、seat 保存，不按当前浏览档案归属。
- 旧标注迁移的 pending 人工确认机制不得削弱。
- 关闭、Esc、返回、切座位统一经过草稿守卫；完成后恢复原滚动和焦点。
- 证据链接跳到对应发言并短暂高亮；事件不可用时说明原因。

结算页显示胜负、本人阵营、得分构成、已有点评、完整时间线和返回首页入口。打开历史或结算不得自动触发付费点评。

## 10. 稳定性与性能

### 10.1 人类操作防重复

- 每次等待人类操作生成新的 `pendingId`，两端从 view 获取。
- 提交 ID 与当前任务不符返回 409，保留草稿并刷新任务。
- 新版本缺少 ID 的旧客户端请求返回 428 并提示刷新，不能把旧操作用于下一阶段。
- 同一任务、相同内容的重复请求只返回已处理结果，不二次执行；不同内容返回冲突。
- 去重缓存有界并随对局保存；服务重启后生成新任务 ID，不自动重放旧请求。
- 狼聊、终止、自爆等写操作网络结果不明时先同步状态，不自动重发。

### 10.2 连接与恢复

- 明确显示连接正常、模型思考、等待本人、重连、故障暂停、保存失败、已结束。
- SSE 心跳与模型耗时分开；保持至少 40 秒失联阈值并覆盖 16 秒心跳测试。
- SSE 与轮询由同一状态模块管理，避免重复订阅和同时补拉。
- 重连按游标去重；玩家与上帝游标分离。
- 切局、离开视图和终局释放连接、定时器和事件监听。
- 恢复必须通过 owner 核对、会话摘要和令牌流程；保存失败必须显示“尚未保存”。

### 10.3 增量渲染与历史

- 玩家节点按 seat 复用，消息按稳定事件 ID 更新。
- 流式字块按动画帧合并，不重绘全部玩家和历史。
- 距底部不超过 80px 时自动跟随；上翻后显示新增条数，不抢滚动。
- 超过 500 条历史启用分段或窗口化，活动消息节点不超过 300 个。
- 窗口化只限制 DOM，不删除存档事件；完整历史仍可分批读取。
- 追加历史后按可见消息 ID 和偏移恢复滚动锚点；图片预留尺寸。

### 10.4 缓存升级

- 新增共享模块、头像和图标纳入离线清单、品牌检查和包校验。
- 验证旧 Worker 控制下首次升级、安装后立即离线、缓存缺项和恢复联网。
- 同代关键资源完整后再启用新版缓存，禁止两代脚本混用。
- 对局中只提示更新，不强制刷新或清空输入。
- 离线只承诺查看缓存内容，不能暗示真实模型仍可运行。

## 12. 版本、交付物与施工纪律

1. 完成任务编号、提交和文件范围。
