## 分配规则与兼容性

1. 性格优先级：用户显式填写的性格 ID／名称／自由文本 > 名册昵称默认性格 > 随机性格。随机分配会避开已指定的库内性格；明确选择同一性格仍允许重复。
2. 头像只读取公开昵称、座位号与 `isHuman`，不读取 `role`、阵营、存活或翻牌状态。桌面、手机、刷新和切换视角使用同一算法。
3. 名册昵称优先保留对应头像，旧昵称和自定义昵称按稳定哈希分配。同局 24 个 AI 以内不重图；同一人物的多个别名同时出现时，座位靠前者保留专属图，其余顺延选取空闲图。
4. 真人仍使用原数字座位标记；图片失败时 AI 也回退为数字，不影响继续操作。
5. 已有存档的人格文本不重写。旧局也能显示头像，不需要存档迁移或增加敏感字段。
6. 现有桌面昵称输入、随机昵称按钮和手机自动取名沿用原入口。手机仍沿用原有的自动命名流程，名册页只是查看入口，不新增手机逐人编辑器。
7. 同步收紧部分旧性格提示词：不把温和等同于固定好人立场，不靠现实誓言或辱骂制造性格，不让萌新刻意犯规则错误；性格仍服从实际阵营目标。

## 资源与构建

- 最终资源：`web/assets/avatars/<id>.png`，24 张 384×384 PNG，总计约 2.31 MB（2.20 MiB）；名册图片懒加载。
- 生成方式：内置 image_gen，24 次独立生成；不是拆分拼图。原始大图保留在生成输出目录，工程中仅做尺寸和调色板导出。
- 最终生成提示词、原始文件名与输出映射：`docs/ai-cast-prompts.json`。
- 使用 imagegen 技能约束一致画风与身份中立；frontend-design 技能指导名册沿用既有配色、字体和响应式布局；Playwright 技能用于桌面／手机浏览器验收。
- 无新增运行时依赖。`web/ai-cast.js` 是 Node 与浏览器共用的公开数据模块，构建时必须同时包含 `src/` 与 `web/`（现有构建脚本已经如此）。
- Service Worker 缓存版本升级到 `ww-v11-cast`；头像按现有静态资源策略缓存，未加载过的头像在离线时回退数字。
- 本轮只更新源码与素材，未覆盖 APK、Windows 或 Electron 发布包。施工方修复合并完成后，按目标平台重新构建并执行 `npm run app:verify`。
