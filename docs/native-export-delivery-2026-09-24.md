# 档案原生导出接线：交付与人工验收

日期：2026-09-24。上轮验收记录在 `docs/fix-plan-2026-09-21.md` §16.37：Android 设备上“导出当前档案”点击不产文件，Electron EXE 的页面按钮也没有调用已有原生保存桥。本轮修正的是页面接线，不改变档案包格式或用户数据。

| 运行环境 | 当前按钮路径 | 成功判据 |
| --- | --- | --- |
| 普通桌面浏览器 | 同源 `<a download>` | 只能提示“已发起下载”，不宣称文件已保存 |
| 普通手机浏览器 | 同源 `<a download>` | 同上 |
| Electron | `window.wwExport.exportProfile(profileId)` | 原生保存框返回字面量 `saved` 且带真实路径才报“已保存” |
| Android WebView | `window.WWExport.exportProfile(profileId)` → SAF `ACTION_CREATE_DOCUMENT` → `window.__wwExportResult` | 同步 `{pending:true}` 只是受理；选定位置且原生流式写完后，回调 `saved` + `content://` 路径才报成功；取消与失败分别显示 |

两端页面只把白名单档案 ID 交给原生桥，包体不通过 JS 桥传输；Android 原生侧仍独立限制本机服务来源和 20MiB，且将 `WebView.getUrl()` 移到 UI 线程。桌面/手机各有运行态单测覆盖保存、取消、失败、非法路径与普通浏览器回退。`npm run gate`（含 1155 项全量测试与临时目录零残留）及 `npm run ui:check -- --full --strict` 已通过。

## 仍需设备上的真实闭环

当前 `adb devices` 显示 `emulator-5554 offline`，因此**没有**用本轮 APK 完成“点导出 → 系统选择位置 → 文件确实落盘 → 从该文件导入”的设备闭环；Electron 也尚未在本轮 EXE 上执行真实系统保存框往返。源码、单测和包内容一致不等于这些人工判据通过。

设备可用后，在新建的测试档案中完成以下动作，并记录版本、APK/EXE 哈希、页面截图、目标文件实际字节数与导入后的新档案 ID：

1. Android：在“我的 → 设备与数据”点“导出当前档案”，确认出现系统“创建文档”，分别测取消、选位置保存、磁盘/权限失败提示；从系统文件管理器核对 JSON 文件存在且非零字节。
2. Android：用界面“导入档案包”选回刚存的文件，预览后确认；应生成副本，原档案/存档不变。完成后不要自动清除用户现有档案。
3. Electron：在玩家中心与档案管理两处分别点导出；核对原生保存对话框、取消文案、保存后的真实文件和导入副本。浏览器版应继续只显示“已发起下载”。
4. 对于任何一处 `saved` 结果，若没有可读文件、文件为 0 字节或缺少真实路径，按失败记录，不用“代码走到了”替代落盘证明。

本轮还修复 Windows 免安装包更新时的存档保护：先把旧包完整暂存，构建失败原位恢复，构建成功后才移走旧包；启动器与说明书版本文案改为从 `release-version.json` 的产品版本生成。构建脚本的成功退出码及 `npm run app:verify` 仍需和最终源码快照绑定。
