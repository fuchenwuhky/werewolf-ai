| 事项 | 唯一责任归属 | 本单只做什么 |
| --- | --- | --- |
| 本机玩家档案、自定义头像、玩家中心、历史分页、导入导出 | 主计划 M1/M2 及对应返修 | 不改接口、存储、头像和页面结构 |

说明：

- “角色卡牌”不是玩家头像、AI 人像、板子选择卡或普通信息面板。本单不得给所有 `.card` 或所有头像批量套框。
- 主计划中“保留现有美术”的原则不变；本单是用户后续明确批准的新卡框例外。软件狼徽、应用图标、启动图、角色立绘、24 张 AI 人像、8 款内置头像继续保留。
- 玩家自定义头像仍由原计划实现，不能被本单替换成固定角色图。
- 不增加 `skinId`、档案偏好字段、皮肤持久化、用户上传卡框、稀有度、付费解锁或新角色。
- 美术技术参数只维护在 [设计包 README](../design/card-frames/v3/README.md)。本单负责施工顺序、责任边界和产品验收；README 原有“施工接入顺序”是本单的技术参考，不另算一份待办。
- 如发现其他业务问题，登记到原任务编号；不能借换肤扩写 API、档案、笔记或引擎。若阻断卡牌接入，先报告依赖，不绕过原有保护。

### SKIN-01：素材落位与唯一版本

1. 从设计源 `assets/` 原样复制上述 17 文件到生产资源目录，不重压透明 PNG，不覆盖角色立绘。
2. 生成可复跑的 SHA-256 清单，记录相对路径、字节数和哈希；源设计与生产副本必须逐字节一致。清单生成与检查沿用现有工具风格，不依赖人工手抄。
3. 核对 R2 小框，而非 `archive/compact-v1/`。PNG 源哈希为 `a230c9ba214ee2dfb3f20ca2f089ee625be6fb2d07ca1888205280914f0e4c4b`；施工仍须实算，不只比文案。
4. 路径由共享层统一提供。桌面 `/`、手机 `/m/` 和两种原生壳都必须能加载，不在每个调用点写相对路径补丁。
5. 将文件清单接入既有静态资源与制品核验，尤其确认新 PNG/SVG 的**二进制内容**有被校验，不能用“文本文件一致”代替。

**交付：**生产素材目录、清单、源/副本核对结果；不触发独立发布。

### SKIN-02：统一卡牌渲染器

`web/card-frame.js` 继续作为产品唯一卡牌入口。推荐新增统一 `CardFrame.mount(host, options)` 或等价接口，内部复用设计包实现；不允许桌面、手机、图鉴分别维护角色映射、SVG 模板和裁切。

必须先解决的接口差异：

- 现有 `CardFrame.html()` 返回字符串框层；设计包 `ReliquaryCards.mount()` 返回节点并替换宿主子节点。二者不能直接同名替换。
- 挂载宿主只能是牌面区域，不能传整个弹层、含按钮/技能说明的容器；不得误删事件绑定和辅助文字。
- 保留 `roleAttrs()/roleAttr()` 等仍被调用的兼容接口，直到调用盘点确认全部迁移。`web/codex.js` 还依赖旧 `wolf/god/villager/third` 分类，不能因新素材命名而改坏分区。
- 新主题映射只在共享层维护：`wolf→wolf`、`god→oracle`、`villager→village`、`third→fate`；未知/不可见→`neutral`。`fate` 仅是暗恋者外观，不是引擎新增阵营。
- 名称来自既有角色资料和国际化层，不把设计演示的固定中文替代生产文案。用安全文本节点写入，不把玩家文字拼成 SVG/HTML。

固定几何与渲染规则：

| 场景 | 卡牌尺寸/规则 | 渲染 |
| --- | --- | --- |
| 手机常驻身份牌 | 52×78 CSS px | R2 小 SVG，姓名在外部 |
| 桌面常驻身份牌 | 62×93 CSS px | R2 小 SVG，姓名在外部 |
| 图鉴/详情参考 | 132×198、210×315 | 大卡材质与单一铭牌 |
| 身份翻牌 | 230×345，空间不足时等比缩小 | 正反面严格相同，不沿用 230×330 |
| 检视卡 | 最高参考 320×480，按可用宽高缩小 | 不遮挡说明、关闭与返回操作 |
| 统一切换 | 组件外框宽度 ≤112px | 使用 R2 小框；不叠加大卡框 |

- 采用设计包的 1024×1536 坐标与画窗裁切；具体路径引用 README/源码，不在两端手抄第二套。
- 移除旧 7/11/10 框带内距、旧 `.inspect-card .inner` 二次缩进以及被替换的框层；图像和新框不能各自缩放一次。
- 大卡只显示一层名称铭牌。图鉴详情的外部标题可以保留，但不能在同一牌面叠两份名称。
- 旧 WebView 的小牌不能只靠容器查询：已知宽度时显式选择 compact；响应式跨过 112px 时两种模式切换正确。
- 装饰层不接收点击，不改变宿主键盘语义。减少动态效果沿用原偏好，不新增动态设置。
- 素材失败：金属 PNG→完整 SVG；小框/完整 SVG 都不可用→CSS 细边框；立绘失败→底衬及可读名称/说明。失败不导致不可关闭或不可操作。
- **独立小卡渲染路径不应仅靠 `display:none` 隐藏大材质后仍请求约 1.94MiB PNG。**生产适配应按需挂载材质；共享一次缓存，大卡需要时再加载。此要求针对卡牌组件自身的请求，SW 为完整离线能力执行的一次性预缓存不在此限；测试须停用或单独标识预缓存流量，不能为达到此项删除离线必需资源。设计展示组件的多层演示 DOM 不是必须照搬的产品结构。

身份可见性约束：

1. `revealed` 表示“当前视角允许知道该身份”，不是直接复制公开翻牌字段。本人牌、公开牌、合法上帝视角、资料图鉴分别沿用原权限来源。
2. 未获知身份一律是相同 neutral 牌背；DOM、URL、ARIA、标题及预加载请求不得带入真实秘密角色。不能先渲染正面再用 CSS 盖住。
3. “我的推测/玩家自称”不能控制系统身份牌的主题、正面或翻牌权限。标注模型继续由原计划负责，本单只确保接线不误用。
4. 未知角色 ID 有中性回退；严禁为了换肤请求上帝视图、全角色私密数据或额外对局接口。

**交付：**共享实现、接口兼容清单、定向测试。先通过后接页面。

### SKIN-03：接入现有真实页面

按以下顺序逐项验收，不能只改独立设计页就报完成：

| 接入点 | 必须保留的行为 | 专项判据 |
| --- | --- | --- |
| 双端图鉴列表 | 选择、分页、搜索、键盘进入 | 四主题正确；选中轮廓清晰；无旧框叠套 |
| 图鉴详情与角色检视 | 规则说明、关闭、返回、焦点归还 | 大卡完整；说明在框外可读；短屏能关闭 |
| 本人身份翻牌 | 原翻牌时机、点击、正反面与关闭 | 2:3；无瞬时露底、正反面错位或双铭牌 |
| 手机/桌面常驻小牌 | 点击查看本人身份、旁侧信息 | 精雕 R2；保持52/62px宽；不扩大占屏 |
| 所有现有牌背入口 | 原权限与未知态 | 统一 neutral＋新内衬，不叠旧 `card_back.png` 自带金框 |
| 其他已有角色牌 | 规则书/结算等实际搜索到的牌面 | 已存在则统一；原本只有文本/小图标的不新增大卡 |

当前已确认的具体接线陷阱：`web/codex.js` 的 `attrStr(CardFrame.roleAttrs(rid))` 会输出普通 `role="seer" faction="god"` 而不是 `data-*`。本单只修卡牌属性序列化，或以统一挂载替代该调用；不能把 `role` 误当作角色 ID 的 ARIA 属性。原有图鉴分区和筛选行为必须保留。

挂载生命周期：

- 不为每次 SSE/view 更新重新创建未变化的卡牌；角色/可见性/尺寸确实变化时再更新。
- 连续打开关闭检视 20 次，不产生重复处理器、重复 DOM 或悬挂尺寸监听器。
- 不把现有 modal、Esc、返回栈或草稿守卫迁移到设计包；本单只验证原能力没有被换肤破坏。
- 卡片图像可以是 52px，但其点击宿主不能因此缩小原计划规定的触区；不为本单再重做所有按钮。

**交付：**逐入口清单、真实产品前后截图、保留行为记录。

### SKIN-04：资源接线与专项验收

缓存由原 M5 机制统一负责。本单仅把新脚本/样式/素材加入清单，并验证本皮肤所需路径，禁止重写网络策略或自动强刷对局。

- 运行资源统一使用生产路径，不依赖 `design/`、开发机绝对路径或第三方域名。
- 现有 HTML 版本引用机制不一定覆盖由 JS 动态生成的图片 URL；对本单动态资源也要确认版本更新方式。不得只改 HTML 链接后声称 PNG/SVG 缓存已解决。
- 以旧 Worker/旧框缓存为起点升级，确认用户按既有更新流程刷新后看到 R2；有未保存输入时不擅自刷新。
- 完成新版本资源预缓存后断网，检查新牌背、小框、大框及必要立绘。资源缺项时降级仍可用，不能把降级当作资源已齐全。
- 缓存结构代次和清单台账沿用既有约定登记；不在文档里指定可能已被另一批占用的 VERSION 值。
- 只验证换肤相关的缓存/性能增量。原计划的全断线、头像强杀、6000事件、原生文件保存矩阵不在本单重新计数。
