## 3. P1 发现的问题（全部为真实成本风险）

### F1 流式请求收到 HTTP 200 + JSON 错误体时不被识别（**已修**）
- **现象**：上游网关忽略 `stream:true`，直接回 200 + `{error:{code:"1308"}}`；应用按 SSE 解析 → 视为"没有内容" →
  校验失败 → 重试 → 永远重复。
- **证据**：假 LLM 注入该形态后，单局空转 **13993 次**调用仍未暂停。
- **修复**：`src/ai/llm.js` 在流式分支按 `Content-Type` 判定，是错误体就按业务码分类（致命即走既有暂停路径）；
  只是 JSON 而非 SSE 就退回非流式重试一次。修复后同一故障 **3 次调用**即正确暂停。

### F2 成本按"次数"计，护栏却按"时间"计（**已修**）
- **现象**：既有预算保护是 `decisionTotalMs`（180s/决策），而**成本是调用次数**。遇到僵持或退化模型时，
  秒回的模型可以在 25 秒内把单局调用刷到近 6000 次 —— 时间预算完全拦不住。
- **证据**：P1 首轮跑出 **38371 次**调用、单局均值 3368 次（基线 55.4 次，**61 倍**）、校验失败 4914 次、
  对局一路打到第 10 天仍在转。
- **修复**：新增 `maxCallsPerGame`（默认 **400**，≈ 实测最大值的 2.5 倍）+ `src/ai/agent.js` 次数护栏。
  超额时**中止本局**（不是暂停）并写明原因 —— 因为暂停依赖断点锚点才能恢复，而实测僵持发生在夜间投刀环节（无锚点），
  暂停会变成谁也恢复不了的死局。修复后同类故障 **400 次即结算**，且结算原因写进 `winReason`。
- 复跑结果：总调用从 38371 降到 3466，用例全绿。

### F3 狼队投刀凑不出多数 → 无限重投（**未修，待你决定规则**）
- **现象**：P1 日志显示 5/7/8/9 号狼人反复投刀、每次输出都合法、但**刀口永远凑不出多数**，于是夜复一夜地重投。
- **影响**：真实对局若出现 2v2 僵持（完全可能），会持续烧调用，直到 F2 的护栏兜底。
- **可选的修法**（需你拍板，因为属于规则）：
  1. 投票轮次上限（例如 3 轮）后由系统裁决：随机取一名获票者 或 本夜空刀；
  2. 或达上限即判定"狼队放弃本夜"，直接进入白天；
  3. 或保留现状，只靠 F2 护栏兜底（代价：那局会被中止）。

### F4 `decisionTotalMs` 只读不写（**未修，小**）
- 该字段被 `askValidated` 读取（缺省 180s），但**没有任何地方设置它** → 无法按板子/节奏调优，测试也难注入小预算。
- 建议：纳入配置（或按 `pace` 派生），这样"预算用尽 → 轻量补救（E1）"这条路径在真实对局里更容易被观察到。

### F5 狼队投票面板：空刀被拒时没有任何可读提示（**已用服务端证据确认，待你确认修法**）
- **现象**：人类是狼、面板停在"选择今晚的刀口"时，直接点「投刀」（不选目标）→ 提交确实被挡住了（**未提交**），
  但 `#pending-hint` 一直是任务描述，玩家不知道自己为什么没投出去。
- **证据（服务端，不靠界面）**：点击前后统计服务端 `wolf_kill` 事件数：**0 → 0**（没有产出新的投刀事件）；
  页面侧 `actionState.target = 0`（0 即"空"，所以这次点击是真空刀，不是误点已选目标）。
- **定性**：**非阻断**（护栏有效、不会提交非法动作），属可读性缺陷。
- **建议修法**：提交前先判目标，若为空就把原因写进 `#pending-hint`（与其它面板的 `pickedTarget()` 一致），
  不要依赖抛异常。工作量约 3 行。

> **自我更正（重要）**：我一度判断"空刀点击触发未捕获 JS 异常"并把 `npm run ui:check` 染红。
> 加装 `unhandledrejection` 记账后实测该点击产生 **0 条**未捕获拒绝 —— 那次异常是我自己的
> "双击测试序列"（先点座位再点提交）造成的，**不是产品缺陷**。相关断言与方法限制已按实情改写。

### F6 `bench:pace` 遇到无样本档位直接崩溃（**已修**）
- **现象**：`npm run bench:pace` 抛 `TypeError: Cannot read properties of undefined (reading 'length')`（`scripts/pace-bench.js:132`）。
- **根因**：投影池只建了 `low`/`high` 两档，而新的 medium 档在日志里没有样本 → `pool['medium']` 未定义。
- **修法**：池按实际 effort 动态建；做不了秩映射时原样返回记录耗时，并把"未投影"次数打到表格上（⚠）。
