# 月蚀圣龛 V3 · 卡牌框素材与接入说明

这是一份独立设计包，供施工方预览和分批接入。当前未替换生产环境的 `CardFrame`，也未修改施工中的 `web/app.js`、`web/m/m.js`。请先完成正在进行的业务改动并交接，再整合卡牌外观。

设计由黑铁骨架、月冠、旧金浮雕、阵营印记和独立文字铭牌组成。真实角色立绘继续复用项目已有素材；本次不重绘角色、不增加角色能力、稀有度或胜利阵营。

## 1. 交付内容

| 文件 | 用途 |
| --- | --- |
| `assets/reliquary-metal.png` | 真实透明背景金属框，1024×1536，2,033,769 字节，约 1.94MiB；大卡默认材质层 |
| `assets/frame-<theme>.svg` | 完整纯矢量框，作为另一种展示模式及 PNG 加载失败时的回退 |
| `assets/compact-<theme>.svg` | R2 精雕薄框，适合 52px、62px 常驻身份牌；每份 5,922 字节 |
| `assets/accent-<theme>.svg` | 金属 PNG 上方的顶部主题印记与画窗细线 |
| `assets/card-back-field.svg` | 中性牌背内衬，内嵌已有狼徽的矢量图形；没有旧牌背的金框，避免双框叠套 |
| `frame-kit.js` / `frame-kit.css` | 独立卡牌组件及裁切规则，命名空间为 `ReliquaryCards` / `.r3-*` |
| `index.html` / `preview.js` / `preview.css` | 独立预览，展示四种已知身份主题、统一牌背和真实使用尺寸 |
| `compact-study.html` / `.css` / `.js` | R2 小卡专项对比：52px／62px 实寸与 192px 细节放大 |
| `archive/compact-v1/` | 第一版小框快照，仅供对比，不部署到生产 |
| `preview-server.cjs` | 只读、仅本机回环地址的预览服务，不启动游戏或访问用户档案 |

正式使用的 SVG 共 16 份：5 个主题，每个主题有 `frame`、`compact`、`accent` 三种文件，另有统一牌背内衬；另有 5 份旧小框归档，不参与生产。所有 SVG 使用 1024×1536 坐标系。生成来源见同目录的 `PROMPTS.md`，验图记录见 `QA.md`；本说明不代替生产接入后的验收。

主题映射固定如下：

| 主题 | 中文外观名 | 使用对象 |
| --- | --- | --- |
| `wolf` | 血月 | 狼人、狼王、白狼王、狼美人、隐狼 |
| `oracle` | 月谕 | 预言家、女巫、猎人、守卫、白痴、骑士、摄梦人、乌鸦 |
| `village` | 炉火 | 村民 |
| `fate` | 命线 | 暗恋者 |
| `neutral` | 未揭示 | 所有不可见身份，以及未知／非法角色 ID 的回退 |

`fate` 的紫色只表达暗恋者的外观分类，不能修改引擎中的 `category`、当前实际阵营或胜负判定。旧代码使用的 `god / villager / third` 外观键，与新素材的 `oracle / village / fate` 是映射关系，不应直接全局替换业务字段。

## 2. 预览方式

在仓库根目录执行：

```powershell
node design/card-frames/v3/preview-server.cjs
```

程序会打印实际访问地址。默认由系统分配空闲端口；需要固定端口时，可先设置专用变量：

```powershell
$env:CARD_PREVIEW_PORT = '3713'
node design/card-frames/v3/preview-server.cjs
```

该服务只接受 GET / HEAD，只公开本设计目录和 `web/assets`。页面真实立绘来自现有 `web/assets/roles/`，因此不要把设计目录单独搬走后误判为缺图。结束时在启动终端按 Ctrl+C。

预览可切换“铸造金属”和“纯 SVG”，并演示统一牌背与已知身份的切换。预览中的“揭示”按钮只是展示控件，不能原样接到真实对局。

小卡精修专项页：在同一服务地址中将 `index.html` 换为 `compact-study.html`。静态对比截图为 `preview-compact-r2.png`；左侧是真实 52／62px，右侧为 192px 放大研究，不是建议把常驻小牌放大。

只读检查可运行：

```powershell
node design/card-frames/v3/verify-kit.cjs
```

该脚本检查 JS 语法、SVG 内部引用、素材路径和隐藏身份契约，不启动服务、不写文件；静态检查不能替代浏览器验图。

## 3. 组件接口

页面先引入 `frame-kit.css`，再在使用组件前加载 `frame-kit.js`。组件没有框架依赖。

```js
const shell = window.ReliquaryCards.mount(cardHost, {
  roleId: 'seer',
  revealed: true,
  render: 'hybrid',
  width: 230,
  assetBase: '/assets/card-frames/v3/',
  artBase: '/assets/roles/',
});
```

上例路径表示建议的生产资源归档位置，**当前没有自动复制到该位置**。接入时必须把文件实际放到约定目录。

| 参数 | 含义与默认行为 |
| --- | --- |
| `cardHost` | 仅容纳卡牌的 DOM 元素；`mount` 会替换其全部子节点，不要传入整个对话框或带操作按钮的容器 |
| `roleId` | 现有角色 ID；只接受内置映射中的 ID，不接受任意素材路径 |
| `revealed` | 只有严格等于 `true` 时才使用角色 ID；含义是“当前视角允许显示该身份”，并非直接照搬玩家的公开翻牌标志 |
| `render` | `'vector'` 使用纯 SVG；其他值使用 `'hybrid'`，即 PNG 金属材质＋SVG 主题装饰 |
| `width` | 可选的正数字宽度，单位 CSS px；缺省为容器宽度，并受 `max-width:100%` 限制 |
| `assetBase` | 卡框目录 URL；自动补齐末尾 `/`；示例页默认 `./assets/`，生产接入必须显式提供 |
| `artBase` | 角色 PNG 目录 URL；自动补齐末尾 `/`；示例页默认路径仅适用于本设计目录，生产接入必须显式提供 |
| `compact` | 传 `true` 强制小卡简版，供不支持容器查询的旧 WebView 使用；已知 `width≤112` 时也会自动标记简版 |

返回值为新建的 `.r3-shell`。展示状态在返回节点上设置，不存在名为 `state` 的挂载参数：

```js
shell.dataset.state = 'selected';   // 选中描光
shell.dataset.state = 'unavailable'; // 不可用灰化
delete shell.dataset.state;         // 普通状态
shell.dataset.render = 'vector';    // 无需重新挂载即可切换渲染模式
```

这些状态只是视觉效果。若宿主是可点击的选择卡，仍由业务层维护 `disabled`、`aria-pressed`、焦点和点击事件，不能仅靠灰色表现禁止操作。

隐藏牌示例：

```js
window.ReliquaryCards.mount(cardHost, {
  revealed: false,
  assetBase: '/assets/card-frames/v3/',
  artBase: '/assets/roles/',
});
```

即使误传 `roleId:'wolf'`，`revealed:false` 也会使用 `neutral`、`card-back-field.svg`、统一朗读文案且不写角色属性。生产调用仍应从经过服务端过滤的玩家视图中取值，不能先加载全量隐藏信息再指望 CSS 遮住。

桌面与手机同源且服务根路径一致时，可使用上述以 `/assets/` 开头的路径。部署到带前缀地址或原生壳时，从应用公开资源根构造绝对 URL；不要在组件里判断 `/m/` 后拼补丁，也不要把本机文件路径传给浏览器。

## 4. 几何、裁切与文字

- 全卡保持严格 2:3。230px 宽的翻牌盒应为 **230×345**，不是旧版 230×330。320px 检视卡为 320×480，52px / 62px 小牌分别为 52×78 / 62×93。
- V3 使用拱形画窗。完整裁切路径集中在 `frame-kit.js` 的 `WINDOW`；小卡改为简化矩形裁切。不要继续套旧框的 `padding:11% 7% 10%`，也不要叠加旧 `.inspect-card .inner` 的边距，否则立绘会被二次缩进。
- 立绘保留原始文件，当前通过 SVG `<image>` 和 `xMidYMid slice` 覆盖画窗。不要覆盖原角色 PNG，也不要把角色图永久裁成带框贴图。
- 所有材质、SVG 装饰与立绘层完全重合，整体缩放；不要把边框用 `object-fit:cover` 再裁一遍，不要用非等比拉伸补尺寸。
- 角色名是 `.r3-title` 的 HTML 文本，设置方式为 `textContent`。禁止把名字、技能、数字、阵营说明烘焙进 PNG。旧 `.r-name` / `.cdx-plate` 接入时只保留一个名称层，避免重影。
- 容器宽度不超过 112px 自动使用 `compact`，隐藏大卡浮雕、PNG 材质和卡面文字，改用专门重绘的小框雕饰。小牌完整名称保留在外部文本或可访问名称中；52px 小牌不硬塞四字角色名。
- 框层使用 `pointer-events:none`，点击、键盘与返回行为仍归宿主。小卡父元素可能 `overflow:hidden`，装饰不能依赖超出卡面才能完整显示。
- 小屏检视同时按可用高度限制宽度，给标题说明与关闭按钮留空间；不能只用 `70vw` 就认定横屏或矮屏不会裁切。
- 组件不含翻转或持续动画；系统减少动态效果规则已提供。接入现有 3D 翻牌时，还需沿用应用档案的减少动态效果偏好。

PNG 读取失败会切换纯 SVG；立绘读取失败会出现暗色底衬并保留可见名称；完整 SVG 或小框 SVG 读取失败时，损坏图隐藏并启用 CSS 细边框。样式文件本身失效的完整产品回退仍需整合阶段验证。自适应简版依赖容器查询；显式 `compact:true` 或传入 `width:52/62` 不依赖该能力，旧 WebView 应由统一适配层选择，不要让每个页面自行判断。

### 4.1 小卡精雕 R2：轻薄，但不是空白细边

根据实际 52px／62px 观感重画，不是将大卡复杂雕花机械缩小：

- 边轨维持窄幅冷银倒角，以亮暗金属棱线形成薄而立体的轮廓。
- 四角使用带镂空的柳叶形哥特扣件；顶部保留微型月冠与切面宝石，底部用月牙收尾。
- 狼人、神职、村民、暗恋者及未知牌背共用同一几何，只切换宝石与嵌线颜色。未知身份必须仍使用 `neutral`。
- 主体装饰不伸出 2:3 画布，不依赖发光／模糊滤镜，不增加动画或位图贴图；五份正式小框合计 29,610 字节。
- 接入本包时直接使用当前 `assets/compact-*.svg`。若已复制旧版小框到生产目录，只替换这五份同名文件并更新资源哈希／离线缓存；不要从 `archive/` 取图。
- 大卡 PNG、完整矢量大框、画窗、组件 API 和 112px 切换阈值均不变。不要为了突出新饰件增大 52／62px 常驻牌，或额外叠加旧边框、粗阴影。

R2 由 `frontend-design` 的实寸优先流程指导，直接编写 SVG；本轮没有重新生图。当前仅更新独立设计包，生产替换仍由施工方接入并验收。

## 5. 施工接入顺序

### 第一批：交接与资源落位

1. 先记录当前施工方提交和未提交文件，完成 `web/app.js`、`web/m/m.js` 的交接，不覆盖正在施工的内容。
2. 将本包所需资产放入一个生产目录，例如 `web/assets/card-frames/v3/`；保留独立设计包供比对。不要复制演示页面整体替换产品页面。
3. 以当前 `web/card-frame.js` 为唯一对外卡框入口，设计统一渲染适配。`ReliquaryCards` 当前只是独立展示 API，不能直接假装与 `CardFrame.html()` 的返回字符串契约兼容。
4. `html()`、`roleAttr()`、`roleAttrs()` 仍有旧调用方时保持兼容，再逐个迁移；不允许桌面、手机、图鉴各维护一份角色到主题映射。稳定后删除被替代实现，避免两代框同时叠加。

### 第二批：正面、图鉴与检视

1. 先接资料图鉴和检视大卡，覆盖有图、缺图、长名字、全部 15 个角色，确认四种主题正确。
2. 修复现有图鉴属性序列化错误：`web/codex.js` 中 `attrStr(CardFrame.roleAttrs(rid))` 当前会输出 `role="seer" faction="god"`，而样式匹配的是 `data-role` / `data-faction`。应使用统一的 `CardFrame.roleAttr(rid)`，或在适配层正确设置 `dataset`；不要继续让实际框体回落到默认主题。
3. 再接本人翻牌和常驻小牌。翻牌盒同步为 2:3，正反面同尺寸；52px 和 62px 必须走简版。
4. 移除被替代的旧框插入、旧命名层和旧边距；保留原点击、焦点、身份查看、关闭与手机返回栈行为。

### 第三批：统一牌背与发布资源

1. 所有未知身份共用 `neutral` 和 `card-back-field.svg`。原 `card_back.png` 保留不覆盖；新内衬仅为避免旧牌背自带边框与新框叠套。未知牌的主题、URL、DOM 属性、可访问名称与可见文字不得因真实角色不同而变化。
2. 本人身份、公开身份、上帝视角、资料图鉴按各自已有的可见性规则接入；卡框层不自行提升权限。不要把“我的推测”显示成系统已揭示身份。
3. 把生产 JS、CSS、17 个新资产及必要旧立绘加入服务离线清单和缓存升级验证，纳入 Android、Windows 目录包及 EXE 的逐文件制品核对。修资源路径不能放宽 CSP 或来源校验。
4. 依据实际产品验收后再判定完成。独立设计页通过，不等于手机壳、Electron、旧缓存升级和真实对局全部通过。

## 6. 接入后的验收清单

- 52 / 62 / 132 / 210 / 230 / 320px：比例正确、无双框、无重复名称、四角与画窗完整。
- 手机 320×568、390×844、横屏与大字号：查看、翻牌、关闭和系统返回均可完成；卡片不挤掉操作按钮。
- 15 个角色、4 个可见身份主题、统一牌背：分类和名称正确；暗恋者外观不影响游戏实际阵营。
- 隐藏角色输入排列变化时：资源 URL、主题、角色属性、朗读文案和截图一致；已知本人身份仍可正常查看。
- PNG 金属层失效：纯 SVG 回退；立绘失效：底衬与名称可见；断网：必需资源已缓存且不混代。
- 点击穿透、键盘访问、焦点归还、减少动态效果与既有翻牌生命周期没有回归。
- 图鉴内层框正确获得主题；不能只检查外层 `.cdx-card` 的属性。
- 当前 `test/card-frame.test.js` 钉住旧版 7/11/10 框带和字符串形状。迁移时改为验证新裁切、统一映射、完整资源与交互契约，不能删除断言后直接宣称通过，也不必为了旧几何保留错误的二次边距。
- 三种候选包中的新资源与同一冻结源码一致，真实产品截图注明提交、尺寸和场景。

此设计包交付的范围是素材、展示组件、演示和接入说明。生产整合、规则回归与原生设备验收由后续施工批次完成；最终实际验图记录以 `QA.md` 为准。
